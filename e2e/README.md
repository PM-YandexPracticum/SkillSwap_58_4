# e2e

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../docs/architecture/fsd.md).

## Зачем эта папка

Автотесты главных сценариев на Playwright: робот открывает сайт в браузере и кликает как пользователь. Набор реализуется в рамках P8-05.

## Как запустить

1. Один раз поставить браузер: `npx playwright install chromium`.
2. `npm run e2e` — Playwright сам поднимет dev-сервер на `http://127.0.0.1:4173` и прогонит тесты.

Порт 4173 должен быть свободен: тесты намеренно не подключаются к уже запущенному серверу из другой рабочей копии.

Файлы — `*.spec.ts`. Unit-тесты Vitest (`*.test.ts`) лежат рядом с кодом в `src/` и сюда не попадают.

## Что внутри

Сейчас покрыты только уже подключённые пользовательские пути:

- `catalog.spec.ts` — карточки, раскрытие секций, поиск Enter/кнопкой, пустая выдача, фильтры, режимы каталога, сортировка и сброс;
- `navigation.spec.ts` — прямая ссылка на навык, 404, защита `/favorites` и `/profile`, охрана шагов регистрации, переход гостя на вход и возврат;
- `startup.spec.ts` — ошибка каждой стартовой коллекции → `/500` → повтор, повторный запрос только упавшего файла и различие ошибки от пустого списка;
- `exchange.spec.ts` — подготовленная сессия, предложение обмена, toast, окно подтверждения, сохранение после перезагрузки, отсутствие дублей и повтор после ошибки записи уведомления.

Проверки с конкретными именами и количеством карточек используют текущие образцы из `public/db/`; при изменении этих образцов вместе с задачами каталога обновляем только ожидаемый контракт теста.

Каждый тест получает отдельный Playwright browser context через стандартный fixture `page`; `storageState` не используется. В сценариях обмена сессия и пустые коллекции намеренно записываются в localStorage как предусловие, потому что настоящий вход ещё не подключён.

Пока не включены сценарии, владельцы которых ещё подключают соседние задачи:

- вход с неверным паролем — P4-09;
- сохранение регистрации в три шага — P6-02, P6-04, P6-06;
- лайк → избранное — P5-07 и P5-08;
- вошедшая шапка и панель уведомлений — P5-09 и P7-05.
- неизвестная сохранённая сессия → гость — P4-09;
- повтор загрузки ленивых обменов и уведомлений — P5-09 и P7-05;
- частично сохранённая регистрация без дублей — P6-06.

Отдельно остаётся интеграционный дефект: после частичного сбоя записи уведомления сохранённый обмен уже имеет `notificationPending`, но карточка каталога пока скрывает ссылку «Подробнее». Восстановление на прямой странице навыка покрыто в `exchange.spec.ts`; восстановление через каталог добавим после согласованного исправления соседней логики.
