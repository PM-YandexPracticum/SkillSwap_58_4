# Автотесты главных сценариев

Playwright открывает SkillSwap в Chromium и проверяет готовые пользовательские пути P8-05. Это сквозные проверки приложения с настоящими формами, Redux и браузерным хранилищем. Проверки отдельных полей, функций и атомарности операций остаются в unit/integration-тестах рядом с `src/`.

## Запуск

```bash
npm ci
npx playwright install chromium
npm run e2e
```

Playwright сам запускает Vite на `http://127.0.0.1:4173` и завершает сервер после тестов. Порт должен быть свободен: подключаться к серверу из другой рабочей копии нельзя. Настройки — [`playwright.config.ts`](../playwright.config.ts). Проверяем десктоп; мобильная версия не входит в ТЗ.

Один файл: `npm run e2e -- e2e/registration.spec.ts`. Видимый браузер: `npm run e2e -- --headed`. Отчёт последнего запуска: `npx playwright show-report`.

## Что проверяем

| Файл | Пользовательский путь |
|---|---|
| `catalog.spec.ts` | Карточки и независимое раскрытие секций; поиск по Enter и кнопке, режимы, город, сортировка, пустая выдача и сброс; догрузка порции без дублей и новая выдача после поиска |
| `navigation.spec.ts` | Прямая ссылка и перезагрузка навыка, 404, закрытые страницы, охрана шагов регистрации, закрытие формы входа с возвратом |
| `auth.spec.ts` | Неверный пароль и исправление, гость → вход → прежний навык, сохранение сессии, неизвестный владелец сессии, выход до завершения ленивой загрузки каталога |
| `registration.spec.ts` | Три шага, фото, превью и редактирование, своя карточка и навык после перезагрузки; ошибка после записи навыка → повтор без дублей и преждевременной сессии |
| `favorites.spec.ts` | Лайк со счётчиком → избранное → перезагрузка → снятие; ошибка записи не создаёт ложный лайк и допускает повтор |
| `exchange.spec.ts` | Обмен → toast, подтверждение и уведомление; сохранение после перезагрузки; частичный сбой уведомления → каталог → повтор прежнего обмена; восстановление сохранённого статуса после ошибки загрузки обменов |
| `notifications.spec.ts` | Два непрочитанных и одно просмотренное уведомление, прочтение и очистка после перезагрузки, граница владельца; ошибки записи без ложного успеха; ручной повтор загрузки, переход к навыку |
| `startup.spec.ts` | Ошибка каждой стартовой коллекции → 500 → повтор только упавшего запроса; пустая сохранённая база отличается от ошибки и сбрасывается с перезагрузкой |
| `helpers.ts` | Общие образцы, настоящий вход, проверка готовности каталога, однократная ошибка записи localStorage |

## Независимость и данные

- Каждый тест получает новый browser context через стандартный fixture `page`. Общего `storageState` и зависимости от порядка запуска нет.
- Вход проходит через форму с демонстрационными данными `public/db/users.json`. Фиксированные ожидания по карточкам используют действующие образцы `public/db/`; при изменении этих данных проверяем ожидания тестов вместе с ними.
- Для проверки владельца и повторов подготовительные записи допустимы через публичный контракт localStorage. Они создаются один раз до сценария и не восстанавливаются при каждом reload.
- Если очищаем localStorage в уже открытом контексте, затем перезагружаем страницу: очистка сама по себе не сбрасывает store и коллекции в памяти.
- Ошибки загрузки воспроизводим ответом HTTP 503, ошибку записи — однократным `QuotaExceededError` у `Storage.prototype.setItem`. Внутренние функции приложения не подменяем, store в `window` не экспортируем.
- Элементы ищем по ролям и подписям. Ожидаем видимое состояние или сетевой запрос; произвольных пауз и автоматических повторных запусков падающего теста нет.

## Отчёты

После запуска доступны HTML-отчёт в `playwright-report/` и JUnit в `test-results/results.xml`. При падении сохраняются скриншот и trace: их можно открыть из HTML-отчёта. Эти папки исключены из Git.
