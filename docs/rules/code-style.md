# Стиль кода

## Именование

| Что | Как | Пример |
|---|---|---|
| Папка слайса (FSD) | `kebab-case` | `catalog-filter`, `offer-card` |
| React-компонент | `PascalCase.tsx` | `UserCard.tsx` |
| Хук | `useXxx.ts` | `useTheme.ts` |
| Утилита | `camelCase.ts` | `getAge.ts` |
| Redux-слайс | `xxxSlice.ts` | `usersSlice.ts` |
| Константы | `UPPER_SNAKE_CASE` | `STORAGE_KEYS` |
| Стили | `Component.module.css` рядом с компонентом | `Button.module.css` |

## Компоненты

- Один компонент — один файл. Пропсы описываем интерфейсом `XxxProps` и экспортируем его.
- Над компонентом — JSDoc: что делает и к какому фрейму Figma относится (`@see Figma: ...`).
- Компоненты entities «глупые»: получают данные пропсами, действия — через слоты (`actions`, `topAction`).
- Функция длиннее ~50 строк или файл длиннее ~300 строк — повод разбить.

## Данные и состояние

- **Никаких мутаций**: создаём новые объекты и массивы (`{ ...user, name }`, `[...ids, id]`, `filter`).
  Исключение — reducers внутри `createSlice` (там работает Immer).
- Магические строки и числа — в константы (`shared/config`).
- Ввод пользователя валидируем схемами `yup` + `react-hook-form`.

## Ошибки

- Асинхронный код — в `try/catch`; пользователю показываем понятное сообщение, а не текст исключения.
- Чтение localStorage всегда в `try/catch` (данные могут быть повреждены).
- `console.log` в коммитах не оставляем.

## Стили

- Только CSS Modules. Цвета, отступы, радиусы, шрифты — CSS-переменные из `src/app/styles/global.css`.
- Никаких захардкоженных цветов — только переменные. Тогда тёмная тема (необязательная фаза 9) включится без переделок.

## README в папках

В каждой папке `src/` лежит `README.md` с краткой аннотацией: зачем папка и что в ней.
Создал новый слайс, сегмент или компонент — добавь в его папку `README.md` и обнови список «Что внутри» у родителя.
