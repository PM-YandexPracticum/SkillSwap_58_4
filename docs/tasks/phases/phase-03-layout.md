# Фаза 3 — Вёрстка блоков и страниц ✅

**Цель:** из компонентов UI-кита собрать блоки, а из блоков — все страницы макета. Пока **без логики**:
кнопки ещё ничего не сохраняют.
**Откуда данные:** UI сущностей получает данные пропсами. Виджеты собирают их из уже готовых селекторов (например, OfferCard в P3-08) или принимают пропсами (NotificationsPanel в P3-15); бизнес-действия пока не сохраняются. В stories и тестах — фабрики `createUser()`, `createSkill()` и `createNotification()`
из `@/entities/*/testing`. Страницы не обращаются напрямую к JSON (`public/db`) и localStorage и не используют фабрики в рабочем коде — линтер это запрещает.
Сейчас данные для страниц загружает `DataProvider` (P4-04), а виджеты и страницы читают их из store через селекторы.
**После фазы:** все экраны открываются по своим адресам и похожи на макет.

Наставник: «из маленьких компонентов собираем побольше, потом виджеты, секции и целые страницы».
Логика (store, фильтры, вход) подключается в фазах 4–7 — там эти же файлы «оживают».
**Общая зависимость:** нужные компоненты фазы 2.

## Архитектурная роль фазы

- **Отвечает за:** сборку блоков, виджетов и страниц из UI-кита и точное соответствие макету.
- **Подключает:** пропсы компонентов, композицию FSD, маршруты страниц и точки, в которые позже подключаются селекторы и действия.
- **Использует:** UI-кит фазы 2, тестовые фабрики и селекторы, когда это уже предусмотрено конкретным блоком.
- **Не дублирует:** хранение данных, запросы, фильтрацию и запись пользовательских действий.
- **Результат для следующих фаз:** готовые визуальные точки интеграции, которые можно оживлять логикой без переписывания разметки.

## Как собирать блоки и страницы

Фаза 3 собирает страницы из готовых компонентов и оставляет бизнес-логику следующим фазам.

- UserCard, UserProfileCard, SkillInfo и SkillGallery переиспользуем как сущности. Они получают данные пропсами и не загружают коллекции самостоятельно.
- Header, Footer, FiltersPanel, OfferCard, OffersSection, OffersCarousel и NotificationsPanel остаются виджетами. Страницы соединяют их через пропсы, callback-и и слоты.
- Для повторяемых карточек используем renderItem; не копируем разметку карточки в каждой секции.
- MainLayout и AuthLayout задают общую рамку. Единственный main и заголовок страницы принадлежат странице, а не лейауту.
- Вёрстка каталога не реализует фильтрацию, поиск, лайки или догрузку. Эти сценарии подключаются задачами фаз 4–5.
- Вёрстка регистрации не сохраняет пользователя и навык. Черновик, валидация и запись подключаются задачами фазы 6.
- Страница навыка получает данные через P7-01, предложение обмена подключается в P7-03, действия уведомлений — в P7-05.
- Для одинаковых состояний используем общие ErrorPage, EmptyState, Modal и токены. Новую почти такую же обёртку создаём только при отличающемся поведении.

Так сохраняется граница слоёв: страница управляет сценарием, виджет собирает блок, сущность показывает данные, shared-компонент отвечает за один элемент интерфейса.
