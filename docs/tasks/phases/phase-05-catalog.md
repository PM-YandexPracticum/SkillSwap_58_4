# Фаза 5 — Каталог и избранное (логика)

**Цель:** главная страница работает целиком.
**После фазы:** секции сортируются и раскрываются, работают фильтры, поиск, лента с догрузкой, лайки, избранное, шапка вошедшего.
Вёрстка уже готова (фаза 3) — здесь её «оживляем».

## Архитектурная роль фазы

- **Отвечает за:** каталог, поиск, фильтры, сортировку, догрузку, лайки и страницу избранного.
- **Подключает:** селекторы данных фазы 4, store запроса и фильтров, `applyFilters`, `useInfiniteScroll`, API текущего пользователя и готовые виджеты фазы 3.
- **Использует:** общие карточки и секции, а также единый контракт пользователя и навыка; результаты передаются в существующую разметку.
- **Не дублирует:** алгоритмы фильтрации, сортировки, догрузки и хранения лайков в отдельных экранах.
- **Результат для следующих фаз:** единый поток данных каталога, на который опираются избранное, профиль и похожие предложения.

## Контур каталога

Каталог собирается из одного последовательного потока:

1. `DataProvider` загружает пользователей, навыки, категории и города; страницы читают их через селекторы.
2. `CatalogPage` получает данные, применённый фильтр и запрос поиска, затем передаёт готовые списки в `CatalogView`.
3. Правила отбора находятся только в `applyFilters` (P5-01): AND между блоками и запросом, OR внутри одного блока.
4. `SearchInput` хранит черновик локально, а применённый запрос живёт отдельно в store. Переходы между секциями и результатами решает страница каталога.
5. `OffersSection` отвечает за сетку и раскрытие секций; `useInfiniteScroll` подключается только к длинным лентам «Рекомендуем», результатов и избранного.
6. `FavoriteButton` меняет лайк через API текущего пользователя; отдельное хранилище лайков не создаём.

| Сценарий | Источник поведения | Подключение |
|---|---|---|
| Фильтры и сортировка | `applyFilters`, `catalogFilter` | P5-01, P5-02, P5-05 |
| Поиск | `SearchInput`, `searchQuery` | P5-03, P5-05 |
| Популярное и Новое | селекторы пользователей | P5-04 |
| Догрузка | `useInfiniteScroll` | P5-06, P5-08 |
| Лайки | API записи пользователя и навыка | P5-07 |
| Вид вошедшего пользователя | сессия и текущий пользователь | P5-09 |

Подробности каждого контракта находятся в соответствующей задаче ниже. Архитектурная карта описывает только пользовательское поведение и слои.

  - **вошедший:** колокольчик, сердечко → `ROUTES.FAVORITES`, имя и `Avatar` текущего пользователя; клик по имени или аватару открывает меню;
  - у обоих: логотип, «О проекте», «Все навыки ▾», поиск и иконка темы — без изменений;
  - проп `isAuth` из вёрстки убираем: шапка сама читает `selectIsAuth`. Для stories и тестов вид задаём состоянием store, а не пропом.
- **Меню пользователя:**
  - «Личный кабинет» → `ROUTES.PROFILE`; «Выйти» — `LogoutButton` из `features/logout`;
  - закрывается по Esc, клику мимо и после выбора пункта; с клавиатуры: Tab до имени, Enter открывает, Esc закрывает и возвращает фокус на кнопку.
- **Выход (`features/logout`):**
  - по «Выйти» согласуем `dispatch(endSession())` (сессия стирается и в store, и в localStorage) и переход на `ROUTES.HOME` с `replace: true`;
  - на главную уходим и со страниц только для вошедших (`/profile`, `/favorites`), иначе `RequireAuth` (P4-08) отправит на вход;
  - после выхода шапка сразу показывает вид гостя, без перезагрузки; после перезагрузки пользователь остаётся гостем;
  - «база» (пользователи, лайки, обмены) не очищается — стирается только сессия.
- **Сердечко в шапке:** `NavLink` на `ROUTES.FAVORITES` подсвечивается на странице `/favorites` и получает `aria-current="page"`; на остальных страницах вид обычный. Счётчика у него нет.
- **Колокольчик:** красная точка — если у текущего пользователя есть непрочитанные уведомления (`selectHasUnread`; уведомления «чьи» — по полю `userId`, это делает P4-07).
  Header управляет открытием переданного слота `notifications`; без содержимого кнопка окно не открывает. Данные панели, «Прочитать все» и «Очистить» подключает P7-05.
- **Правило FSD для шапки:** виджет не импортирует другие виджеты. Меню «Все навыки» (`widgets/categories-menu`) и окно уведомлений (`widgets/notifications-panel`)
  шапка получает слотами-пропсами от `MainLayout` в `app/layouts` — так же, как `OffersCarousel` получает карточку через `renderItem`. Фичи (`logout`, `skill-search`) шапка импортирует напрямую.
- **Тесты (`Header.test.tsx`, `LogoutButton.test.tsx`)** — через `renderWithProviders` и `preloadedState` (как задать сессию — в [testing.md](../../rules/testing.md)), данные — `createUser()`:
  - гость: видны «Войти» и «Зарегистрироваться», нет колокольчика и имени;
  - вошедший: видны имя и аватар текущего пользователя, нет «Войти»;
  - есть непрочитанное уведомление текущего пользователя — точка на колокольчике; нет — точки нет;
  - меню: клик по имени открывает «Личный кабинет» и «Выйти», Esc закрывает;
  - «Выйти»: в store сессии больше нет, в localStorage — тоже, адрес — `ROUTES.HOME`, шапка в виде гостя;
  - на `/favorites` сердечко подсвечено (проверяем по `aria-current="page"` у ссылки, а не по классу).
