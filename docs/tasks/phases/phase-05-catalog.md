# Фаза 5 — Каталог и избранное (логика)

**Цель:** главная страница работает целиком.
**После фазы:** секции сортируются и раскрываются, работают фильтры, поиск, лента с догрузкой, лайки, избранное, шапка вошедшего.
Вёрстка уже готова (фаза 3) — здесь её «оживляем».

### P5-01 · Логика фильтров ✅ 🔴
> **Что нужно сделать:** сделать состояние фильтров в store (режим, подкатегории, пол, города, сортировка) и чистую функцию
> `applyFilters`, которая оставляет подходящих пользователей с учётом строки поиска и сортирует по дате.
> По ТЗ фильтры комбинируются логикой **AND**: пользователь должен подходить под поиск И режим И навыки И пол И город;
> внутри одного блока несколько отмеченных значений — «любой из». Это ядро каталога — каждый фильтр и их сочетания покрываем тестами.

- **Уже готово:** типы фильтров и селектор `selectActiveFiltersCount`.
- **Режимы (решение тимлида):** «Хочу научиться» проверяет `learnSubcategoryIds` автора карточки; «Могу научить» — подкатегорию его предлагаемого навыка; «Всё» — оба варианта. Поиск всегда только по названию предлагаемого навыка.
- **Результат P5-01:** реализованы действия состояния, публичный API и `applyFilters`: AND между блоками и поиском, OR внутри блока, поиск по названию предложения, обе сортировки, удаление и сброс фильтров.
- **Файлы:** `src/features/catalog-filter/model/`, `src/features/catalog-filter/lib/applyFilters.ts` + тесты
- **Issue:** [#59](https://github.com/PM-YandexPracticum/SkillSwap_58_4/issues/59) · PR [#154](https://github.com/PM-YandexPracticum/SkillSwap_58_4/pull/154)
- **Зависит от:** P4-03 — для подключения загруженных данных; чистое ядро реализовано и проверено независимо на фабриках.
- **Статус на 11.11.2026:** Done, влита в `develop`; исполнитель: `kirill-ai-dev`.
- **Проверки:** 523 теста проходят, включая 53 проверки P5-01; lint, TypeScript и сборка проходят; покрытие `applyFilters`, reducer и selectors — 100 % строк, функций и ветвей.

### P5-09 · Шапка вошедшего и выход 🟡
> **Что нужно сделать:** научить шапку выбирать вид по сессии: гостю — «Войти» и «Зарегистрироваться», вошедшему — колокольчик,
> сердечко, имя и аватар. Меню по клику на имя: «Личный кабинет» и «Выйти»; «Выйти» стирает сессию и ведёт на главную.
> Колокольчик здесь пока только показывает точку — сами уведомления подключит P7-05.
> Это первая задача, где виден весь «контур» вошедшего пользователя: кто вошёл — решает сессия, его имя и аватар — селектор «текущий пользователь».

- **Зависимости для реализации:**
  - вёрстка обоих видов `Header` готова в P3-04: сейчас вид переключает проп `isAuth`; в этой задаче подключаем сессию и текущего пользователя;
  - сессия (P4-05): `selectIsAuth`, `selectSession` и `endSession()` из `@/entities/session` — выход одним действием стирает сессию и в store, и в localStorage;
  - после P4-09 будут готовы вход и селектор `selectCurrentUser` из `@/entities/user` — вошедший пользователь (`PublicUser`) или `null` у гостя;
  - `Dropdown` (P2-08) с `align="end"` — в его stories есть пример меню «Личный кабинет / Выйти»; `Avatar` размера `sm` (P2-04);
  - маршруты — `ROUTES.HOME`, `ROUTES.LOGIN`, `ROUTES.REGISTER_STEP_1`, `ROUTES.FAVORITES`, `ROUTES.PROFILE` из `@/shared/config`.
- **Контур гостя и вошедшего (одно правило на весь проект):**
  - «Вошёл ли пользователь» спрашиваем только у `selectIsAuth`; «кто именно вошёл» — только у `selectCurrentUser`.
    Свой поиск «пользователь по `userId` из сессии» в компонентах и фичах не пишем — так поведение гостя везде одинаковое.
  - Данные о других людях (карточки, страница навыка) от входа не зависят — меняются только кнопки и доступные действия.
  - Пароль в шапку не попадает: `selectCurrentUser` отдаёт `PublicUser`.
- **Шапка по видам:**
  - **гость:** «Войти» → `ROUTES.LOGIN`, «Зарегистрироваться» → `ROUTES.REGISTER_STEP_1`;
  - **вошедший:** колокольчик, сердечко → `ROUTES.FAVORITES`, имя и `Avatar` текущего пользователя; клик по имени или аватару открывает меню;
  - у обоих: логотип, «О проекте», «Все навыки ▾», поиск и иконка темы — без изменений;
  - проп `isAuth` из вёрстки убираем: шапка сама читает `selectIsAuth`. Для stories и тестов вид задаём состоянием store, а не пропом.
- **Меню пользователя:**
  - «Личный кабинет» → `ROUTES.PROFILE`; «Выйти» — `LogoutButton` из `features/logout`;
  - закрывается по Esc, клику мимо и после выбора пункта; с клавиатуры: Tab до имени, Enter открывает, Esc закрывает и возвращает фокус на кнопку.
- **Выход (`features/logout`):**
  - по «Выйти» — `dispatch(endSession())` (сессия стирается и в store, и в localStorage), затем переход на `ROUTES.HOME` с `replace: true`;
  - на главную уходим и со страниц только для вошедших (`/profile`, `/favorites`), иначе `RequireAuth` (P4-08) отправит на вход;
  - после выхода шапка сразу показывает вид гостя, без перезагрузки; после перезагрузки пользователь остаётся гостем;
  - «база» (пользователи, лайки, обмены) не очищается — стирается только сессия.
- **Сердечко в шапке:** на странице `/favorites` подсвечено (`useLocation`, путь `ROUTES.FAVORITES`), на остальных — обычное. Счётчика у него нет.
- **Колокольчик:** красная точка — если у текущего пользователя есть непрочитанные уведомления (`selectHasUnread`; уведомления «чьи» — по полю `userId`, это делает P4-07).
  Открытие окна, «Прочитать все» и «Очистить» здесь не делаем — это P7-05; пока по клику ничего не происходит.
- **Правило FSD для шапки:** виджет не импортирует другие виджеты. Меню «Все навыки» (`widgets/categories-menu`) и окно уведомлений (`widgets/notifications-panel`)
  шапка получает слотами-пропсами от `MainLayout` в `app/layouts` — так же, как `OffersCarousel` получает карточку через `renderItem`. Фичи (`logout`, `skill-search`) шапка импортирует напрямую.

  - есть непрочитанное уведомление текущего пользователя — точка на колокольчике; нет — точки нет;
