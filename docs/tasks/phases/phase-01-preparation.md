# Фаза 1 — Подготовка

**Цель:** договориться о цветах, шрифтах и иконках, поставить библиотеки и инструменты.
**После фазы:** у всех одинаковое окружение, Storybook открывается, можно верстать.

Задачи 👑 меняют `package.json` или общие настройки — их делают **тимлид или помощник**, в общий Todo они не попадают.
Остальные — для команды. Токены, иконки, картинки, Storybook и окружение уже готовы, так что фазу 2 можно брать. Из моков первой нужна P1-05: от её id зависят P1-07 и P1-08.

### P1-04 · Подготовка к тестам: образец и помощники 🟡
> **Что нужно сделать:** подготовить всё, чтобы команде было легко писать тесты, и показать пример. Шаги:
> 1. Реализовать `getAge` (возраст по дате рождения) и написать к ней первый тест — это образец, по которому все будут писать свои.
> 2. Сделать фабрики `createUser()` и `createSkill()`: они возвращают готового тестового пользователя и навык, а в тесте меняешь
>    только нужное поле — `createUser({ gender: 'female' })`. Их же используют stories.
> 3. Сделать `renderWithProviders`: он отрисовывает компонент в тесте вместе со store и роутером — без него компонент
>    с `useSelector` или `<Link>` в тесте падает. Для этого в `app/store` нужна функция `createAppStore()`, которая создаёт новый store.
> 4. Коротко описать в `docs/rules/testing.md`: где лежат тесты, как их называть и запускать, что проверяем — со ссылкой на образец.

- **Уже готово:** Vitest, jsdom и Testing Library настроены (`vitest.config.ts`, `src/setupTests.ts`); `describe` / `it` / `expect` и матчеры
  вроде `toBeInTheDocument` работают без импорта и известны TypeScript; иконки импортируются в тестах (`like.svg?react`); заглушка `getAge`.
  `npm run test:coverage` пока не запускается — пакет покрытия ставит тимлид в P1-10, в этой задаче он не нужен.
- **Файлы:** `src/entities/user/lib/getAge.ts` + `getAge.test.ts`, `src/entities/user/lib/createUser.ts` (новый),
  `src/entities/skill/lib/createSkill.ts` (новый), `src/app/store/index.ts`, `src/app/test/renderWithProviders.tsx` (новый),
  `docs/rules/testing.md` (новый), `docs/rules/README.md`
- **Зависит от:** —
- **Готово, когда:**
  - тест `getAge` проверяет три случая: обычный, день рождения сегодня, день рождения завтра (ещё не исполнилось);
  - `createUser()` без аргументов возвращает пользователя со всеми полями `User`, с аргументом — меняет только переданные поля;
  - есть пример теста компонента через `renderWithProviders`;
  - `testing.md` — не длиннее страницы, ссылка на него есть в `docs/rules/README.md`; `npm run test` и `npx tsc --noEmit` зелёные.

> Почему файлы лежат так: фабрикам нужны типы `User` и `Skill`, поэтому они в `entities` — их можно импортировать из тестов
> и stories любых слоёв выше. `renderWithProviders` нужен store из `app`, поэтому он в `app/test/` и импортируется только в тестах.
