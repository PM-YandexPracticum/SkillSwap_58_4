# Фаза 6 — Регистрация (логика)

**Цель:** можно зарегистрироваться за 3 шага и сразу попасть в каталог, где уже есть своя карточка.
**После фазы:** новый пользователь сохраняется в «базе», появляется в каталоге и может войти.
Защита закрытых страниц уже готова (P4-08); вход реализован отдельно в P4-09.
Все поля проверяются по [validation.md](../../rules/validation.md). Вёрстка форм — из фазы 3.

## Архитектурная роль фазы

- **Отвечает за:** последовательность регистрации, черновик, валидацию шагов, создание пользователя и переход в приложение.
- **Подключает:** `registerSlice`, guard и lifecycle маршрутов, общие правила validation, категории и подкатегории, загрузку превью и API пользователей.
- **Использует:** формы и UI-кит фазы 3, данные и сохранение фазы 4, связь категорий из P6-03.
- **Не дублирует:** авторизацию входа, общую защиту страниц и отдельные правила хранения файлов или сессии.
- **Результат для следующих фаз:** один сериализуемый черновик и предсказуемый контракт создания пользователя.

- **Результат:** `registerSlice` хранит сериализуемый черновик и монотонный `completedStep`; `RegisterStepGuard` возвращает на шаг 1 при прямом заходе без пройденного предыдущего шага. `RegisterDraftLifecycle` сбрасывает состояние только при фактическом выходе из `/register/*`, а переходы между шагами и StrictMode не стирают данные.
