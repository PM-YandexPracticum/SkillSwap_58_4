# Фаза 8 — Финиш

**Цель:** у пользователя нет «тупиков», всё похоже на макет, главные сценарии проверены.
**После фазы:** проект готов к приёмке.

## Архитектурная роль фазы

- **Отвечает за:** устойчивость приложения, общие пустые состояния, доступность, сквозные проверки и финальную сверку.
- **Подключает:** `ErrorBoundary`, `EmptyState`, E2E и интеграционные тесты, проверки клавиатуры и макета.
- **Использует:** готовые сценарии фаз 4–7 и существующие UI-компоненты; исправления возвращаются в слой, которому принадлежит проблема.
- **Не дублирует:** бизнес-логику и локальные обходы ошибок внутри отдельных страниц.
- **Результат для следующих фаз:** подтверждённый MVP без белых экранов и тупиков, готовый к приёмке.

После аварии «На главную» перезагружает приложение с учётом BASE_URL; обычная /500 сохраняет навигацию и повтор загрузки. Добавлены тесты, stories, README и снимок интерфейса.

### P8-03 · Пустые списки 🟢
> **Что нужно сделать:** сделать один общий компонент «Ничего не нашлось» (иконка, текст, кнопка) — для результатов поиска, избранного и уведомлений.
> Где пусто — показываем, что делать дальше, а не белое место.
> Проверить, что везде, где данные грузятся, виден Loader.

- **Что уже есть:** CatalogView и NotificationsPanel выводят локальные тексты пустоты, `shared/ui/EmptyState` пока отсутствует. Выносим только общее отображение (текст, необязательные иллюстрация и действие), не загрузку, фильтрацию или чтение store. Каталог различает пустую базу и отсутствие совпадений, избранное — пустой список и отфильтрованный результат. Для уведомлений сохраняем текст и компактный вид панели, кнопку возврата в каталог там не добавляем. Ожидание загрузки и ошибка не должны превращаться в «Ничего не нашлось»; стартовую загрузку уже обрабатывает DataProvider.
