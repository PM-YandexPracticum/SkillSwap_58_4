# Дорожная карта SkillSwap

Полный план: от текущего состояния до работающего макета.
Каждая задача = одна карточка на [канбан-доске](https://github.com/orgs/PM-YandexPracticum/projects/133/views/1) = одна ветка = один PR.

**Основная работа (MVP) — 86 задач** (фазы 1–8), из них 7 👑 для тимлида и помощника. Дополнительные фичи — ещё 9, по желанию (фаза 9).
Требования — по [ТЗ наставника](../requirements/mentor-tz.md) от 31.10.2026; наши отличия от него — в [разделе 16б ТЗ](../requirements/tz.md#16б-сверка-с-тз-наставника-3110).

## MVP по ТЗ (то, без чего нет командного зачёта)

Каталог с догрузкой по 6 · фильтры · страница навыка с прямым заходом `/skill/:id` · вход и сохранение данных ·
уведомление и toast о предложенном обмене · «Личные данные» в профиле · создание навыка (это регистрация) · `/favorites` · 404 и 500.

## Объём проекта

- **Только десктоп**, всегда 3 колонки. Pixel perfect не нужен — визуальное сходство. Адаптив — по желанию.
- **Данные — внутри приложения** за слоем `entities/*/api`: образцы по 2–3 на сущность, изменения в localStorage. Остальные моки команда заполняет по образцу. По ТЗ наставника JSON должны лежать в `public/db` — перенос после наполнения моков (👑 P4-10).
- **Пагинация** (так её называет наставник) — догрузка по 6 карточек при прокрутке, номеров страниц нет.
- **Поиск и фильтры комбинируются логикой AND** (по ТЗ); поиск — по Enter или клику на лупу.
- **Календарь и карусель — библиотеки**, стилизуем под макет.
- **Заглушки без реакции:** футер (Контакты, Блог, Политика, Соглашение), Google / Apple, «поделиться» и «⋯», «Сообщить об ошибке»; 4 раздела кабинета.
- **Уведомления номинальные:** «Вы предложили обмен …» → «Перейти»; «Прочитать все», «Очистить», toast.
- **Гость** при лайке или «Предложить обмен» идёт на вход и возвращается обратно; после регистрации — всегда каталог.

## Уровни задач

| Уровень | Для кого | Объём |
|---|---|---|
| 🟢 **Лёгкая** | первая задача в проекте | один компонент или файл, до полудня |
| 🟡 **Средняя** | после 1–2 лёгких | несколько файлов, логика + UI, до дня |
| 🔴 **Сложная** | самые уверенные или в паре | связывает несколько слоёв, 1–2 дня |
| 👑 **Тимлид** | тимлид или помощник, своей веткой и PR | меняет `package.json` или общие настройки |

**План наставника по неделям** (ориентир, сроки могут смещаться — главное держать темп):

| Неделя | По ТЗ наставника | Наши фазы |
|---|---|---|
| 1 | Знакомство с проектом, нарезка задач | 0–1 |
| 2 | Вёрстка | 2–3 |
| 3 | Логика | 4–7 |
| 4 | Правки | 8 |

```
Фаза 1 → Фаза 2 (UI-кит) → Фаза 3 (блоки и страницы) → Фаза 4 (данные и вход) ─┬─ Фаза 5 (каталог) ──────┐
                                                                                 └─ Фаза 6 (регистрация) ─┴─→ Фаза 7 → Фаза 8 ┄┄ Фаза 9 ⭐
```

- Фазы 2–3 — вёрстка без логики, фазы 4–7 — логика: так советует наставник («из маленьких компонентов — блоки, из блоков — страницы»).
- Задачу можно взять, когда все задачи из «Зависит от» влиты в `develop`. Зависимости идут только назад.
- **Одновременно у человека — одна задача.** Следующую — после того, как сдал текущую.
- Тимлид держит задачи в **Backlog** и переносит в **Todo**, когда их зависимости готовы, — так в Todo всегда только то, что можно брать.
- **Старт:** первыми — P1-01 (токены), P1-02 (иконки) и 👑 P1-11 (Storybook): от них зависит вся фаза 2. Остальные задачи фазы 1 — параллельно.
- **Свободным людям:** P4-01 («база») и P4-05 (сессия) ни от чего не зависят — их можно брать раньше, пока идёт вёрстка.

## Как переносить задачу на доску

1. Тимлид создаёт issue по шаблону **Feature** в колонке **Backlog**: название `[ID] Название`, например `[P2-02] Кнопки Button и IconButton`.
2. Поля шаблона: «Что нужно сделать» — одноимённый блок задачи; «Скрины / макет» — скриншот фрейма; «Acceptance criteria» — «Готово, когда» и общий критерий фазы; «Связанные задачи» — ссылки на «Зависит от».
3. Тимлид вписывает в задачу плана строку `- **Issue:** [#N](ссылка)` — так видно, какие задачи уже на доске.
   Уже созданы: #1 — фаза 0, #2 — P1-11, #3 — P1-14 (их названия с `[FEATURE]` можно поменять на `[ID]`).
4. Задача готова к работе → **Todo**. Дальше — по [tasks/README.md](README.md#как-взять-задачу).
