## Что должно работать в MVP

Пользователь должен уметь:

- открыть каталог и страницу навыка напрямую;
- искать предложения, фильтровать их и догружать список;
- войти, зарегистрироваться и сохранить данные;
- предложить обмен и увидеть уведомление;
- открыть профиль и избранное;
- увидеть понятные страницы 404 и 500.

Проект рассчитан на десктоп. Данные работают внутри фронтенда: начальные JSON лежат в **public/db**, операции проходят через слой **entities/*/api**, изменения сохраняются в localStorage. Дополнительные функции фазы 9 не входят в обязательный MVP.

## Уровни задач

| Уровень | Объём | Рекомендация |
|---|---|---|
| 🟢 Лёгкая | один компонент или небольшой файл | первая задача участника |
| 🟡 Средняя | несколько файлов, UI и логика | после первой принятой задачи |
| 🔴 Сложная | несколько слоёв и сценариев | для уверенного участника или пары |
| 👑 Тимлидская | общие настройки, зависимости и архитектура | тимлид или помощник тимлида |

## Порядок сборки

    Фаза 0 → Фаза 1 → Фаза 2 → Фаза 3 → Фаза 4
                                          ├─ Фаза 5 ─┐
                                          └─ Фаза 6 ─┴─ Фаза 7 → Фаза 8

- Фазы 2–3 дают переиспользуемые компоненты и готовую вёрстку.
- Фаза 4 подключает хранение данных, store, загрузку и сессию.
- Фазы 5–7 подключают пользовательские сценарии поверх готового API.
- Фаза 8 проверяет приложение целиком после интеграции предыдущих фаз.

Незавершённая зависимость не запрещает перенести карточку в Todo. В описании задачи фиксируем, что именно ещё нужно для интеграции. Исполнитель согласует общий API и файлы до начала работы.

## Правила работы с доской

1. Одна карточка — одна задача и один PR.
2. Один участник одновременно ведёт одну задачу.
3. Backlog — задачи, которые пока не входят в ближайшую очередь.
4. Todo — ближайшая очередь уже назначенных задач.
5. In Progress — работа ведётся в ветке задачи.
6. Review — PR ждёт проверки.
7. Done — PR влит в develop и issue закрыта. Для P8-07 отдельно зафиксировано принятие по решению тимлида без изменений кода; открытая issue #86 отражена в отчёте.
8. После каждого влитого PR обновляются файл фазы, [отчёт](report.md) и счётчики снимка в roadmap. Описание порядка фаз меняется только при изменении плана.
