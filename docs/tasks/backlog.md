## Решено (в основном — на онбординге наставника)

| Вопрос | Решение |
|---|---|
| Моки | По 2–3 образца на сущность; до 40–50 пользователей команда заполняет по образцу (P1-05…P1-08) |
| Лайки | Поле `likesCount` у пользователя (у всех разное), счётчик у сердечка; `likedUserIds` — для избранного |
| «Смотреть все» | Секция раскрывается с 3 до 9 карточек, остальные сдвигаются вниз; повторный клик — свернуть |
| Пагинация | По словам наставника — догрузка при прокрутке: спиннер ~1 с и ещё 6 карточек; в «Рекомендуем», результатах и избранном. Номеров страниц нет |
| «Рекомендуем» | Все пользователи в случайном порядке, лента с догрузкой; повторы между секциями — нормально |
| Поиск | Поле с лупой, как в макете; запуск по Enter или клику на лупу, «×» очищает — как сказал наставник (в макете крестика нет) |
| Сочетание фильтров | По ТЗ — AND между фильтрами и поиском; внутри блока (несколько городов) — «любой из» |
| Критерии приёмки из исходного ТЗ | Взяты: Lighthouse Performance ≥ 80, Accessibility ≥ 90, покрытие ядра ≥ 70 % — P8-07 |
| Описание навыка | ≤ 500 символов, как в исходном ТЗ |
| Меню «Все навыки» | Статичное; в футере — отдельная страница `/skills` |
| «О проекте» | Страница команды с GitHub-ссылками |
| Регистрация | 3 отдельных маршрута; прямой заход на шаг 2–3 → шаг 1 |
| «Хочу научиться» | Как в макете: списки с чекбоксами (1:1673, 1:1717) + правило связи наставника; можно несколько |
| «Может научить» | Ровно один навык со своим названием + категория + подкатегория |
| «О себе» | При регистрации пустое, заполняется только в профиле |
| Календарь, карусель | Библиотеки, стилизуем под макет (ставит тимлид, P1-10) |
| Уведомления | Номинальные: «Вы предложили обмен …» → «Перейти»; «Прочитать все». Тосты и «принятие» обмена не делаем |
| Смена пароля | В «Личных данных» по «Изменить пароль» — дополнительное поле (P7-06) |
| Заглушки | Футер, Google / Apple, «поделиться», «⋯», «Сообщить об ошибке» — без реакции; 4 раздела кабинета — «Раздел в разработке» |
| Адаптив | Только десктоп, 3 колонки; адаптив — по желанию, на приёмке не оценивается |
| Pixel perfect | Не нужен — визуальное сходство |
| Бекенд и данные | «База» внутри приложения за слоем `entities/*/api` (образцы в JSON, изменения в localStorage) — P4-01. Простой бекенд наставник разрешает, его можно подключить позже, поменяв только слой api |
| `package.json` и зависимости | Меняет только тимлид в `develop` (задачи 👑) |
| CI/CD | Не развиваем: проверки локально; Husky — по желанию (P1-14). `ci.yml` из шаблона оставлен как есть |
| Сообщения коммитов | Commitizen и `npm run commit` — P1-14 (issue #3) |
| Storybook | Наставник очень рекомендует — ставим (P1-11), каркас уже есть |
| Хеширование пароля | Не нужно: пароль учебный |
| Тёмная тема, ICS, бейджи, чат, PWA | Вне MVP — [фаза 9](phases/phase-09-extras.md) |
| Шаги 2 и 3 регистрации, календарь | Есть в макете: шаг 2 — 1:1497…1:1717 (календарь 1:1541), шаг 3 — 1:1761, превью — 1:1799 |
| Пол | Можно «Не указан» — это вариант списка в макете (1:1585) |
| Окно после «Предложить обмен» | Есть в макете: «Вы предложили обмен. Теперь дождитесь подтверждения…» (1:1977) |
| Куда вести гостя при лайке / «Предложить обмен» | На регистрацию; после неё — обратно на ту же страницу (1:3052) |
| Уведомления «принял обмен», «Очистить», тосты (в макете 1:2148) | Не делаем — уведомления номинальные по наставнику |
| Секции «Точное совпадение / Новые идеи» (часть фреймов) | Не делаем — «Популярное / Новое / Рекомендуем» по наставнику |

## Идеи вне плана

Не берём, пока не закончены фазы 1–8. Нужна — оформляем задачей по [шаблону](TEMPLATE.md).

| Идея | Зачем |
|---|---|
| Адаптив до 1024 px | Сайт не ломается на ноутбуке с маленьким экраном |
| Фильтры и поиск в адресной строке | Можно поделиться ссылкой на подборку |
| Синхронизация между вкладками | Уведомления обновляются во всех открытых вкладках |
| Скелетоны карточек | Красивее, чем спиннер, пока грузятся данные |
| Валидация «только почта Яндекса» | Наставник разрешил как пример кастомной ошибки |
