## Колонки доски

| Колонка | Кто двигает | Что значит |
|---|---|---|
| **Backlog** | только тимлид и помощник | задачи следующих этапов; ещё не включены в ближайшую очередь команды |
| **Todo** | тимлид | ближайшая очередь после текущих In Progress / Review; незавершённые зависимости перечислены в задаче и не запрещают Todo |
| **In progress** | разработчик | взял задачу (назначил себя исполнителем), работает в своей ветке |
| **Review** | разработчик | открыл PR, ждёт проверки |
| **Need fix** | тимлид | в PR есть замечания — разработчик забирает обратно в In progress |
| **Done** | тимлид | PR влит в `develop` |

Todo не означает, что уже готовы все зависимости для интеграции. Перед работой сверяем их состояние, доступный API и общие файлы. Взятые задачи сохраняют исполнителя и In Progress, даже если ждут другую задачу. Переносы карточек и изменения описаний в GitHub выполняются только по согласованию с тимлидом.

Общая P8-02 — исключение: участники добавляют себя отдельными мини-PR с `Refs #81`. Принятые вклады отмечаем в отчёте, а общую задачу закрываем после добавления всей команды.

## Как взять задачу

1. В колонке **Todo** выбери задачу своего уровня (🟢 → 🟡 → 🔴). **Одновременно — только одна задача.**
2. Нажми **Assign yourself** и перетащи карточку в **In progress**.
3. `git checkout develop && git pull`, затем ветка `feature/<id>-<название>`, например `feature/p2-02-buttons`.
4. Сделал → коммит только своих файлов → push → PR в `develop` → карточку в **Review**.
5. Замечания (карточка в **Need fix**) → правишь в той же ветке → снова **Review**. Влили → **Done**.

## Номера мест в макете (1:2870)

Числа вроде `1:2870` в задачах, JSDoc и stories — номер места в [макете Figma](https://www.figma.com/design/40gXmyAoxwwnb9kBxI5B8y/SkillSwap-Red.1-), как адрес.
Зачем: и исполнитель, и ревьюер открывают ровно то место, по которому сделан компонент, и сверяют с ним цвета, размеры и отступы.

- **Где в задаче:** строка «Где в макете», например «Регистрация 3 шаг» (1:1761).
- **Как открыть по номеру:** допиши к ссылке на макет `?node-id=` и номер, заменив двоеточие на дефис:
  `.../SkillSwap-Red.1-?node-id=1-2870` — шапка на экране каталога.
- **Как узнать номер самому:** войди в свой аккаунт Figma, кликни по нужному месту — в адресной строке появится `node-id=1-2870`.
- **Одно и то же на разных экранах** (шапка, кнопки) — это разные копии, у каждой свой номер. Подходит любой, по которому открывается нужное место.
- **Куда записать номер:** в JSDoc над компонентом — `@see Figma: «Шапка» (1:2870)` — и в описание каждой story.

## Сроки

Ориентиры, сколько задача может быть в работе и на проверке:

| Уровень | В работе (In progress) |
|---|---|
| 🟢 Лёгкая | до 1 дня |
| 🟡 Средняя | до 2 дней |
| 🔴 Сложная | до 3 дней |

- **Ревью** — в течение дня после открытия PR; замечания (Need fix) исправляем тоже в течение дня.
- Не успеваешь или застрял — **сразу пиши в чат**, что мешает: поможем или разделим задачу.
- Задача висит дольше срока, а исполнитель молчит, — тимлид или помощник может передать её другому.
- План наставника по неделям и как он ложится на фазы — в [roadmap.md](roadmap.md#фазы).

## Как не сделать работу дважды

- Почти все файлы из «Файлы» уже существуют как **заглушки с JSDoc**: открываем и дописываем, рядом новый файл не создаём.
  Новые файлы в задачах помечены «(новый)».
- Строка **«Уже готово»** в задаче — то, что сделано заранее. Это не переделываем.
- Сделанная задача получает ✅ в файле фазы (`### P2-02 · Кнопки Button и IconButton ✅ 🟢`) и строку в [отчёте](report.md) — их добавляет тимлид или помощник после влития PR.
- Прежде чем завести новую задачу, тимлид ищет по [фазам](phases/README.md): нет ли её уже в плане.

## Задачи тимлида и помощника 👑

Всё, что меняет `package.json` (библиотеки, Storybook, Commitizen, Husky, Playwright) и общие настройки, делает тимлид или помощник —
по ТЗ наставника помощник дублирует обязанности тимлида. Работают так же, как все: своя ветка и PR в `develop`.
В плане такие задачи помечены 👑 и в общий Todo не попадают.

## Новая задача, которой нет в плане

1. Тимлид оформляет её по [TEMPLATE.md](TEMPLATE.md) в нужной фазе со следующим свободным ID.
2. Создаёт issue в колонке **Backlog** и переносит в **Todo**, когда её можно брать.
