## Колонки доски

| Колонка | Кто двигает | Что значит |
|---|---|---|
| **Backlog** | только тимлид и помощник | черновики задач; ждут, пока будут сделаны задачи, от которых зависят |
| **Todo** | тимлид | задача готова, её можно брать. Тимлид следит, чтобы здесь всегда было что взять |
| **In progress** | разработчик | взял задачу (назначил себя исполнителем), работает в своей ветке |
| **Review** | разработчик | открыл PR, ждёт проверки |
| **Need fix** | тимлид | в PR есть замечания — разработчик забирает обратно в In progress |
| **Done** | тимлид | PR влит в `develop` |

## Как взять задачу

1. В колонке **Todo** выбери задачу своего уровня (🟢 → 🟡 → 🔴). **Одновременно — только одна задача.**
2. Нажми **Assign yourself** и перетащи карточку в **In progress**.
3. `git checkout develop && git pull`, затем ветка `feature/<id>-<название>`, например `feature/p2-02-buttons`.
4. Сделал → коммит только своих файлов → push → PR в `develop` → карточку в **Review**.
5. Замечания (карточка в **Need fix**) → правишь в той же ветке → снова **Review**. Влили → **Done**.

## Как не сделать работу дважды

- Почти все файлы из «Файлы» уже существуют как **заглушки с JSDoc**: открываем и дописываем, рядом новый файл не создаём.
  Новые файлы в задачах помечены «(новый)».
- Строка **«Уже готово»** в задаче — то, что сделано заранее. Это не переделываем.
- Сделанная задача получает ✅ в файле фазы (`### P2-02 · Кнопки Button и IconButton ✅ 🟢`) — ставит автор в своём PR.
- Прежде чем завести новую задачу, тимлид ищет по [фазам](phases/README.md): нет ли её уже в плане.

## Задачи только для тимлида 👑

Всё, что меняет `package.json` (библиотеки, Storybook, Commitizen, Husky, Playwright) и общие настройки, делает тимлид в `develop`.
В плане такие задачи помечены 👑 и в общий Todo не попадают.

## Новая задача, которой нет в плане

1. Тимлид оформляет её по [TEMPLATE.md](TEMPLATE.md) в нужной фазе со следующим свободным ID.
2. Создаёт issue в колонке **Backlog** и переносит в **Todo**, когда её можно брать.
