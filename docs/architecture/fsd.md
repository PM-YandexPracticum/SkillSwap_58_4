# Архитектура SkillSwap (Feature-Sliced Design)

Макет: [Figma — SkillSwap (Red.1)](https://www.figma.com/design/40gXmyAoxwwnb9kBxI5B8y/SkillSwap-Red.1-)
Методология: [feature-sliced.design](https://feature-sliced.design/ru/)

## 1. Слои

```
src/
├── app/        # Инициализация: провайдеры, роутер, store, лейауты, глобальные стили
├── pages/      # Страницы = композиция виджетов под конкретный URL
├── widgets/    # Крупные самостоятельные блоки UI (шапка, панель фильтров, карточка предложения)
├── features/   # Действия пользователя, которые несут бизнес-ценность (лайк, фильтр, вход)
├── entities/   # Бизнес-сущности: типы, слайсы, селекторы, api, «глупый» UI
└── shared/     # Переиспользуемое без бизнес-логики: ui-кит, api-клиент, config, lib
```

### Главное правило: импорт только вниз

```
app → pages → widgets → features → entities → shared
```

- Слой может импортировать **только из слоёв ниже**.
- Слайсы одного слоя **не импортируют друг друга** (`features/login` ✗→ `features/register`).
  Исключения обсуждаем с тимлидом (сейчас их нет: общее — например, правила валидации — живёт в `shared`).
- Импорт из слайса — **только через его `index.ts`** (публичный API):
  ```ts
  import { UserCard } from '@/entities/user'               // ✓
  import { UserCard } from '@/entities/user/ui/UserCard'   // ✗
  ```
- `shared/ui` — без общего barrel-файла, импорт по компоненту: `@/shared/ui/Button`.

## 2. Структура слайса

```
entities/user/
├── index.ts          # публичный API — всё, что можно использовать снаружи
├── model/            # types.ts, *Slice.ts, selectors.ts, схемы валидации
├── api/              # доступ к «базе» (единственное место, которое знает, откуда данные)
├── lib/              # чистые функции-хелперы (покрываются unit-тестами)
└── ui/               # React-компоненты
```

Сегменты создаются по необходимости — пустых папок не держим.

## 3. Redux

- Store: `app/store`. Новый слайс подключается одной строкой в `app/store/rootReducer.ts`.
- `RootState` и `AppDispatch` — **глобальные типы** (объявлены в `app/store/index.ts`),
  поэтому селекторы в entities/features пишутся как `(state: RootState) => ...` без импорта из app.
- Хуки: `useAppDispatch`, `useAppSelector` из `@/shared/lib/store`.
- Данные сущностей (users, skills, exchanges...) — в **entities**; состояние UI-сценария
  (фильтры, поиск, мастер регистрации, избранное) — в **features**.
- Никаких мутаций вне `createSlice` reducers; в остальном коде — только новые объекты/массивы.

## 4. Данные: «база» внутри приложения

Бекенда нет, поэтому «база данных» живёт в браузере — за слоем доступа, который потом можно заменить на настоящую БД.

```
компонент → селектор / thunk → entities/<сущность>/api/<сущность>Api.ts → shared/api/mock-db (createMockCollection)
                                       ↑ только этот слой знает,                 ↑ образцы: mock-db/seed/*.json
                                         откуда берутся данные                     изменения: localStorage
```

| Что | Где |
|---|---|
| Образцы данных — по 2–3 на сущность (пользователи, навыки, категории, города, обмены, уведомления) | `src/shared/api/mock-db/seed/`; пользователи и навыки — по частям: `users/sample.json`, `users/part-N.json` |
| Изменения: регистрация, лайки, профиль, обмены, уведомления | localStorage, ключи `skillswap_db_<коллекция>` (`shared/config/mockDb.ts`) |
| Сессия и тема | localStorage, ключи — `shared/config/storageKeys.ts` |
| Фото образцов | `public/images/avatars/`, `public/images/skills/` |
| Загруженные пользователем фото | data URL внутри записи (до 1 МБ — у localStorage ~5 МБ на сайт) |

- **Переход на настоящую БД:** меняются только `entities/*/api/*Api.ts` (или реализация `createMockCollection`) — компоненты и слайсы не трогаются.
- `resetMockDb()` сбрасывает все изменения к образцам — для тестов и проверки с чистого листа.
- Остальных пользователей и навыки команда заполняет по образцу — задачи P1-05…P1-08.

**Сущности:** пользователь, навык, категория (с вложенными подкатегориями), город, сессия, обмен, уведомление.

**Модель пользователя** (`entities/user/model/types.ts`) — по подсказкам наставника:
- `id`, `email` (логин), `password` — учебный, хранится как есть; в UI не выводим (компоненты получают `PublicUser`);
- `name`, `avatarUrl`, `birthDate` (возраст считаем), `gender`, `cityId` → город из справочника;
- `about` — «О себе»: при регистрации **пустое**, заполняется только в «Личных данных» и тогда появляется на странице навыка;
- «Может научить» — **ровно один** навык со **своим названием**: `teachSkillId` → навык (название + категория + подкатегория + описание + фото);
- «Хочет научиться» — **одна или несколько подкатегорий**: `learnSubcategoryIds`;
- `likesCount` — сколько раз лайкнули: сортировка «Популярного» и счётчик у сердечка; у всех разный;
- `likedUserIds` — кого лайкнул сам пользователь: отсюда страница `/favorites`;
- `createdAt` — дата регистрации: сортировка «Нового» и результатов; у всех разная.

**Демо-вход:** любой email из образцов (например, демо-аккаунт `u03`, Мария, `maria@example.com`)
и общий тестовый пароль `SkillSwap2025`. Это тестовые данные, не используй их нигде, кроме этого проекта.

**Валидация** — всего, что вводит пользователь: правила в [docs/rules/validation.md](../rules/validation.md),
лимиты в `shared/config/validation.ts`, проверка в каждой форме.

### Каталог: как работают секции (слова наставника)

| Секция | Порядок | Сколько видно |
|---|---|---|
| Популярное | по `likesCount`, от большего | 3, «Смотреть все» → 9 (секции ниже сдвигаются), повторный клик — свернуть |
| Новое | по `createdAt`, от новых | так же: 3 ⇄ 9 |
| Рекомендуем | все пользователи в случайном порядке | лента: при прокрутке спиннер ~1 с и ещё 6 карточек |
| Подходящие предложения (фильтры / поиск) | сортировка «сначала новые / старые» | плашки выбранных фильтров + лента по 6 |

Карточки между секциями могут повторяться. Колонок всегда 3 — только десктоп. Числа — в `shared/config/catalog.ts`.
**«Пагинация» у наставника — это именно догрузка по 6 при прокрутке** (в ленте «Рекомендуем», в результатах и в избранном), номеров страниц нет.
Поиск — поле «Искать навык» с лупой (макет 1:2819): запуск по Enter или клику на лупу, «×» очищает (наставник).
**Фильтры и поиск комбинируются логикой AND** (ТЗ); внутри одного блока несколько отмеченных значений — «любой из».

### Общие компоненты

| Компонент | Как сделан |
|---|---|
| Лента с догрузкой | `shared/lib/hooks/useInfiniteScroll` + `Loader` (номеров страниц нет) |
| Календарь | `shared/ui/DatePicker` — **обёртка над библиотекой** (тимлид ставит, например, react-datepicker) |
| Карусель | `shared/ui/Carousel` — **обёртка над библиотекой** (embla-carousel-react или swiper) |
| Категория ↔ подкатегория | `entities/category/ui/CategorySubcategorySelect`: категория ограничивает подкатегории, подкатегория сама подставляет категорию |
| Плашка | `shared/ui/Tag` с `onRemove` — выбранные фильтры и «Хочу научиться» на шаге 2 |

`widgets/offers-carousel` получает карточку через `renderItem` — страница передаёт туда `OfferCard`,
потому что виджет не может импортировать другой виджет.

**Заметки дизайнера в макете** (фиолетовые) описывают сценарии: «По клику на «Предложить обмен» открывается модалка с пояснением»,
«…кнопка меняется на состояние «обмен предложен»», «После того как пользователь предложил обмен, пришло уведомление»,
«Если пользователь регистрировался через кнопку «Зарегистрироваться» / «Предложить обмен»» — от этого зависит, куда он вернётся.

**Где макет и наставник расходятся — делаем как сказал наставник:**
- уведомления: в макете «Николай **принял** ваш обмен» — у нас номинальные «Вы предложили обмен …»; «Прочитать все», «Очистить» и тосты — делаем (ТЗ наставника 31.10);
- секции у вошедшего: в 1:2148 / 1:2106 «Точное совпадение / Новые идеи», в 1:2904 / 1:2996 «Популярное / Новое» — у нас «Популярное / Новое / Рекомендуем».

## 6. Объём работ: решения команды и наставника

- **Только десктоп**, 3 колонки. Pixel perfect не нужен — нужно визуальное сходство. Адаптив — по желанию, на приёмке не оценивается.
- **Заглушки, которые ничего не делают:** в футере — «Контакты», «Блог», «Политика конфиденциальности», «Пользовательское соглашение»;
  кнопки Google / Apple; «поделиться» и «⋯» на странице навыка; «Сообщить об ошибке» на 404 / 500.
- **Заглушки разделов кабинета:** «Заявки», «Мои обмены», «Избранное», «Мои навыки». Рабочий раздел — только «Личные данные».
- **Регистрация** — 3 отдельных маршрута; на шаг 2 и 3 попасть можно только кнопками, прямой заход → шаг 1.
- **Уведомления номинальные:** «Вы предложили обмен …» → «Перейти»; «Прочитать все» → в просмотренные, они не кликаются.
- **Тёмная тема и остальные доп. фичи** — вне MVP (фаза 9).
- Заполненные поля сохраняются (профиль, регистрация, лайки).

Открытые вопросы — в [backlog.md](../tasks/backlog.md).

## 7. Нейминг

- Папки слайсов — `kebab-case` (`catalog-filter`), компоненты — `PascalCase.tsx`, хуки — `useXxx.ts`.
- Один компонент — один файл. Стили — CSS Modules рядом: `Button.module.css`.
- Цвета, отступы, шрифты — только CSS-переменные из `app/styles/global.css`.
