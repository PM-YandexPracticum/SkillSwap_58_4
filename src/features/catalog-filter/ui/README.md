# src/features/catalog-filter/ui

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **ui** слайса `catalog-filter` — React-компоненты. Получают данные пропсами или из store через селекторы.

**Текущее состояние:** в P3-07 реализованы режим, навыки, пол автора, города и сброс. В P5-02 выборы и общий сброс подключены к `catalogFilter` в store; вывод результатов, плашки и сортировка остаются в P5-05. `ActiveFilters` и `SortToggle` получили управляемую вёрстку в P3-10. Redux-ядро и `applyFilters` готовы в P5-01.

## Что внутри

- `ActiveFilters.tsx` — управляемый ряд плашек выбранных фильтров над результатами; подписи и удаление передаются пропсами
- `CityFilter.tsx` — Чекбоксы «Город» из справочника entities/city: первые `CATALOG.CITIES_VISIBLE` видны сразу, остальные — по «Все города ▾»
- `GenderFilter.tsx` — Радио «Пол автора»: Не имеет значения / Мужской / Женский
- `ModeFilter.tsx` — Радио «Всё / Хочу научиться / Могу научить»
- `ResetFiltersButton.tsx` — Кнопка «Сбросить ×» рядом с «Фильтры (N)»
- `SkillsFilter.tsx` — Дерево чекбоксов «Навыки»: категория раскрывается в подкатегории, «Все категории» показывает остальные
- `SortToggle.tsx` — Переключатель сортировки результатов «Сначала новые» ⇄ «Сначала старые» (по дате регистрации)

## Поведение P3-07

- `SkillsFilter` / `CityFilter` получают справочники пропсами. `FiltersPanel` читает их готовыми селекторами. Загрузка, ошибки загрузки и повторный запрос принадлежат странице: здесь нет запросов и обращений к JSON/localStorage.
- `CATALOG.CATEGORIES_VISIBLE` — шесть категорий из макета; `CATALOG.CITIES_VISIBLE` — пять городов. Если данных больше, работают «Все категории» / «Все города» и «Свернуть». Когда весь список уже виден, лишней кнопки нет.
- Выбранные подкатегории — единственный источник состояния родителя. Пусто / часть / все дают соответствующий Checkbox. Локальный `useReducer` переиспользует `catalogFilterReducer` и действия P5-01, отдельная логика выбора категории не копируется. Redux store не меняется.
- Выбор сохраняется после сворачивания списков; категория без подкатегорий отключена и не предлагает раскрытие. Пустой справочник оставляет подписанную группу без чекбоксов.
- `ModeFilter` / `GenderFilter` переиспользуют RadioGroup с уникальными именами; `SkillsCategory.tsx` — внутренний компонент строки дерева с Checkbox и IconButton.
- `FilterGroup.module.css` — общие заголовки, строки и кнопки двух списков; общий класс `action` задаёт цвет, hover и focus текстовых действий, включая сброс; `SkillsFilter.module.css` — только вложенность дерева; `ResetFiltersButton.module.css` — оформление текстового сброса. Стили RadioGroup не дублируются.
- `ResetFiltersButton` передаёт `onClick`. Без обработчика остаётся номинальной кнопкой и не отправляет форму; в каталоге обработчик сбрасывает общий `catalogFilter`.

## Макет, доступность и проверки

[Figma: 1:2860](https://www.figma.com/design/40gXmyAoxwwnb9kBxI5B8y/SkillSwap-Red.1-?node-id=1-2860). Строки чекбоксов — минимум 32 px, согласно уточнению задачи; у вложенных строк отступ 32 px и промежуток 4 px. Есть подписи групп, уникальные id, `aria-expanded` / `aria-controls` и управление с клавиатуры. Декоративные SVG скрыты от скринридера.

Состояния, не нарисованные отдельно в Figma: пустые справочники, отсутствие подкатегорий, скрытие ненужной кнопки полного списка и длинные подписи. Цвет текста зелёных кнопок локально немного затемнён через `color-mix` существующих токенов: исходный `--color-accent-strong` даёт на белом 4,29:1, ниже WCAG AA 4,5:1. Глобальные токены и UI-кит не меняются.

Stories рядом с компонентами показывают обычное, раскрытое, выбранное, частично выбранное и пустое состояния. Данные stories загружает `loadSeed` в loaders; тесты проверяют пользовательские действия, границы списков, независимость категорий и изменение справочника.

## Плашки и сортировка P3-10

`ActiveFilters` получает `items: { id, label, color? }[]` и `onRemove(id)`, скрывает пустой список и переиспользует `Tag` с вариантом `filter`. `SortToggle` получает `value: SortOrder` и `onChange`, запрашивает противоположный порядок. Оба компонента управляемые: не читают store и не сортируют/фильтруют карточки. Преобразование состояния store в эти пропсы и соединение со списком — P5-05.

Рядом лежат CSS Modules, тесты callbacks и клавиатуры, stories обычного/пустого/длинного списка и обоих порядков сортировки.
