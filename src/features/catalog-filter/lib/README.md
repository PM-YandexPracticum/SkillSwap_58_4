# src/features/catalog-filter/lib

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **lib** слайса `catalog-filter` — чистые вспомогательные функции. Первые кандидаты на unit-тесты.

## Что внутри

- `applyFilters.ts` — Чистая функция фильтрации каталога. Не мутирует входной массив. Правило из ТЗ: все фильтры и поиск комбинируются логикой AND; внутри одного блока несколько отмеченных значений — «любой из» (иначе два города дают пустой результат). Учитывает режим («Хочу научиться» — по `learnSubcategoryIds`, «Могу научить» — по подкатегории навыка), подкатегории, пол, города, строку поиска (только по названию предлагаемого навыка) и сортировку по `createdAt`. Обязательно покрыть unit-тестами — это ядро бизнес-логики каталога

## Контракт P5-01

`applyFilters(users, skills, filters, query)` получает полные массивы через параметры и возвращает новый массив `PublicUser`. Массивы, объекты и выбранные фильтры не изменяет. Навык ищет по `user.teachSkillId`; отсутствующий навык не подходит под поиск по названию или выбранную предлагаемую подкатегорию. Дата сортировки — `user.createdAt`, при равных датах порядок сохраняется.

Режим относится к автору карточки: `learn` — его `learnSubcategoryIds`, `teach` — подкатегория его предложения, `all` — совпадение в любом из двух наборов. Несколько выбранных подкатегорий и городов работают через OR; между блоками и поиском — AND. Пустой блок подкатегорий не ограничивает тематику; `learn` при этом требует хотя бы одну желаемую подкатегорию, `teach` — существующее предложение. Режим `all` без подкатегорий не ограничивает список. Поиск обрезает пробелы по краям и не учитывает регистр; имена, описания и названия подкатегорий не участвуют.

Загрузка данных, вызов функции из каталога, применение поиска по Enter и управление панелью относятся к P4-03 / P5-02 / P5-03 / P5-05.

Для точного поиска навыков и выбранных id используется общий `createLookup` с бинарным поиском. Индексы строятся один раз на вызов `applyFilters`, не внутри обхода пользователей. Поиск подстроки в названии остаётся строковым; фильтрация списка и сортировка результата сохраняются.
