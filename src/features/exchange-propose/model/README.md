# src/features/exchange-propose/model

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сценарий предложения обмена: сборка записей, сохранение через операции сущностей и состояние интерфейса.

## Что внутри

- `proposeExchange.ts` — сборщик данных и сценарий сохранения P7-03: формирует запись обмена со стабильным id и текст «Вы предложили обмен …», а `persistExchangeProposal` последовательно вызывает операции сущностей P4-07 и безопасно повторяет недостающую запись после частичного сбоя.

- `useProposeExchange.ts` — состояние кнопки и окна, переход гостя с `state.from`; ответ старой операции не меняет страницу после перехода, выхода или смены пользователя. Повторная загрузка в StrictMode не запускает второй запрос обменов.
- `proposeExchange.test.ts` — подготовка обмена со стабильным id и текста без предварительной копии уведомления.
- `persistExchangeProposal.test.ts` — параллельные предложения, прочитанное уведомление, очистка и повтор после сбоя отметки завершения.

`notificationPending` хранится в записи обмена. Пока поле `true`, повтор дописывает уведомление и завершает операцию даже после перезагрузки; старые записи без поля считаются завершёнными. Уведомление сохраняет дату первоначального обмена. После очистки уведомлений завершённый обмен их заново не создаёт. Склонение имени — общая функция `shared/lib/formatRecipientName`, без отдельной зависимости.

Сценарий не вызывает `fetchNotifications` перед каждой записью. `ensureExchangeNotification` атомарно возвращает существующую запись или создаёт её; в store попадает фактическая запись. Проверка дубля обмена выполняется в очереди коллекции без предварительного `getAll` в API. Полный список обменов загружается только при инициализации или восстановлении после обнаруженного дубля.

Уведомление создаётся только внутри сохранения из фактически записанного обмена: дата и связи не берутся из повторной попытки. `ExchangeProposal` содержит только `exchange` и `message`.

При открытии страницы хук вызывает общий `loadExchangesIfNeeded`: одна попытка из `idle`/`failed`, без повторов в `loading`/`succeeded` и без цикла после ошибки. Признак завершённого предложения берётся из общего `selectHasProposed`, как в карточке каталога.
