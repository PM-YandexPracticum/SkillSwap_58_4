# src/features/register/ui

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **ui** слайса `register` — React-компоненты. Получают данные пропсами или из store через селекторы.

**Текущее состояние:** StepCredentials подключает общую проверку email и пароля и проверку занятости email (P6-02); StepProfile подключает проверку полей шага 2 (P6-04); StepSkill собирает шаг 3 с валидацией и превью из P6-05; сохранение и завершение регистрации — P6-06.

## Что внутри

- `StepCredentials.tsx` — email, пароль с подсказкой, «Далее», ссылка «Войти». Передаёт проверенные CredentialsValues в onNext, принимает начальные значения черновика; сохранение выполняет страница. OAuthButtons подключает страница
- `StepProfile.tsx` — Шаг 2 «Расскажите немного о себе»: слот аватара, Имя, Дата рождения (DatePicker) + Пол (Select: Не указан / Мужской / Женский) в одну строку, Город (Select с поиском), «Категория навыка, которому хотите научиться» и «Подкатегория…» — CategorySubcategorySelect в режиме `multiple` (списки с чекбоксами). Форма на react-hook-form и `createProfileStepSchema`; `onNext` получает проверенные значения, `onBack` — текущие без проверки, `defaultValues` — значения черновика. «О себе» здесь нет — только в профиле
- `StepSkill.tsx` — Шаг 3 «Укажите, чем вы готовы поделиться»: колонка формы со слотами `skillForm` (`SkillForm` из features/skill-create) и `previewModal` (`SkillPreviewModal`). Слайсы features не импортируют друг друга, поэтому слоты подставляет страница. Иллюстрация и подпись «Так другие люди смогут увидеть ваши предложения и предложить вам обмен!» справа — в RegisterLayout

- `StepProfile.module.css` — геометрия второго шага и строки даты/пола.
- `StepProfile.test.tsx` — поля, «Продолжить» неактивна для пустой формы, значения в `onNext` и `onBack`, подстановка черновика, ошибки имени, возраста, города и «Хочу научиться», клик/Enter без нативной отправки формы

- `StepCredentials.test.tsx` — отправка кликом/Enter, ошибки после blur, границы пароля, занятый email и его исправление, восстановление черновика, подсказка и видимость пароля
- `StepCredentials.stories.tsx` — пустая и заполненная форма, реальная ошибка занятого email 1:2627; каждая история получает свой Redux store с тестовым пользователем

- `StepSkill.module.css` — ширина и отступ колонки шага
- `StepSkill.test.tsx` — слоты формы и окна

Первый шаг использует `credentialsSchema` через `yupResolver`, без ручного разбора ошибок Yup. Режим `onTouched` показывает ошибку после первого ухода из поля и обновляет её при исправлении. `isValid` определяет доступность «Далее», `isSubmitting` блокирует кнопку во время отправки. Уникальность email проверяется готовым `selectUserByEmail`; новых загрузок форма не запускает. Ошибка занятого email переводит фокус к полю. Черновик и переходы остаются ответственностью страницы.

Второй шаг работает так же: `mode: 'onTouched'`, `isValid` блокирует «Продолжить». У `Select` нет события потери фокуса, поэтому выбор города считается уходом с поля; для «Хочу научиться» проверка запускается при каждом изменении подкатегорий. Города и категории форма читает из store, аватар подставляет страница слотом `avatarUpload`.

В Figma 1:2548 кнопка «Далее» нарисована активной даже при пустых полях. В рабочей форме применяется правило `docs/rules/validation.md`: неверные значения и текущая отправка блокируют кнопку.

В состоянии Figma 1:2627 под корректным паролем указано «Надёжный». Это не отдельная оценка сложности: после успешной проверки общей схемой подсказка заменяется на этот текст; при ошибке снова показывается правило, которое нужно исправить.
