# src/features/register/model

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **model** слайса `register` — данные и логика: типы, Redux-слайс, селекторы, схемы валидации.

**Текущее состояние:** черновик и прогресс шагов работают (P6-01): `draftUpdated`, `stepCompleted`, `registerReset`, селекторы `selectCompletedStep` и `selectRegisterDraft`. Схема первого шага использует общие emailField/passwordField; форма подключает её через yupResolver, а уникальность email проверяет по загруженным пользователям. Схема второго шага (P6-04) собрана из общих полей имени, даты рождения и города. Шаг 3 проверяет навык и фото (P6-05). `completeRegistration` (P6-06) сверяет справочники, поочерёдно сохраняет навык и пользователя, обновляет store через entity thunks, создаёт сессию и сохраняет в черновике стабильные IDs повтора. После частичной записи повтор обновляет существующую запись навыка или пользователя, не создавая дубликаты.

## Что внутри

- `registerSlice.ts` — Черновик регистрации из 3 шагов. «Назад» не стирает введённое, «Закрыть ×» — сбрасывает черновик. После «Готово» — всегда каталог.
  - `draftUpdated(partial)` — дописать поля шага в черновик, остальные не трогаются
  - `stepCompleted(step)` — шаг пройден; номер только растёт (вернулся на шаг 1 и снова «Далее» — шаг 2 остаётся пройденным)
  - `registerReset()` — пустой черновик и 0 пройденных шагов; при выходе из регистрации вызывает `RegisterDraftLifecycle` в app/router. После успеха fulfilled очищает данные, сохраняя прогресс до перехода в каталог, чтобы guard не вернул на первый шаг
  - `selectCompletedStep`, `selectRegisterDraft` — для охраны шагов и заполнения полей после «Назад»
- `registerSlice.test.ts` — тесты редьюсеров и селекторов
- `registerActions.ts` — общие действия сброса, отмены и стабильной попытки; отдельный файл устраняет цикл импорта между thunk и слайсом
- `completeRegistration.ts`, `completeRegistration.test.ts` — согласованная запись регистрации, повтор после отказа и повторное чтение связанных записей после перезагрузки
- `schema.ts` — Шаг 1: email + пароль (`credentialsSchema`). Уникальность email проверяется отдельно — по загруженным пользователям. Шаг 2: `createProfileStepSchema(cityIds, categories)` — имя, дата рождения (14–100 лет), пол (можно `null` — «Не указан»), город из справочника, «Хочу научиться» — от 1 до 10 уникальных подкатегорий из справочника, принадлежащих отмеченным категориям. Восстановленный черновик сверяется тем же `syncCategorySelection`, который использует UI; аватар в схему не входит и проверяется при выборе файла. Все поля — общие из `@/shared/lib/validation`
- `schema.test.ts` — правила обоих шагов: границы, пустые значения и тексты ошибок
- `types.ts` — Данные, накопленные по всем шагам. Хранятся в Redux, поэтому только сериализуемые значения: `File` не кладём в store; фото хранятся как готовые data URL (проверены `validateImageFile`, уменьшены `fileToDataUrl`), при сохранении (P6-06) повторно не сжимаются

## Уход со страницы и повтор

`completionRequestId` связывает результат с текущим запросом. Страница при размонтировании вызывает `registrationCancelled(requestId)`, а сброс черновика также снимает эту связь. После каждого ожидания координатор проверяет, что запрос ещё актуален: старый ответ не создаёт сессию, не очищает новый черновик и не открывает каталог. Reducer игнорирует поздние результаты другого запроса.

Уже начатая операция API может дописать свою коллекцию после отмены. Новую транзакцию или откат хранилища для этого не добавляем. Пока черновик сохранён, повтор читает записи по прежним id, проверяет их принадлежность попытке и продолжает запись. После ошибки можно изменить email или фото и повторить; навык обновляет `updateDataSkill`, пользователя — существующий `updateDataUser`.
