# src/features/register/model

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **model** слайса `register` — данные и логика: типы, Redux-слайс, селекторы, схемы валидации.

**Текущее состояние:** черновик и прогресс шагов работают (P6-01): `draftUpdated`, `stepCompleted`, `registerReset`, селекторы `selectCompletedStep` и `selectRegisterDraft`. Схема первого шага использует общие emailField/passwordField; форма подключает её через yupResolver, а уникальность email проверяет по загруженным пользователям. Схема второго шага (P6-04) собрана из общих полей имени, даты рождения и города. Схема шага 3 — P6-05. Описания ниже — целевой сценарий.

## Что внутри

- `registerSlice.ts` — Черновик регистрации из 3 шагов. «Назад» не стирает введённое, «Закрыть ×» — сбрасывает черновик. После «Готово» — всегда каталог.
  - `draftUpdated(partial)` — дописать поля шага в черновик, остальные не трогаются
  - `stepCompleted(step)` — шаг пройден; номер только растёт (вернулся на шаг 1 и снова «Далее» — шаг 2 остаётся пройденным)
  - `registerReset()` — пустой черновик и 0 пройденных шагов; при выходе из регистрации вызывает `RegisterDraftLifecycle` в app/router; после успешного завершения сброс подключает P6-06
  - `selectCompletedStep`, `selectRegisterDraft` — для охраны шагов и заполнения полей после «Назад»
- `registerSlice.test.ts` — тесты редьюсеров и селекторов
- `schema.ts` — Шаг 1: email + пароль (`credentialsSchema`). Уникальность email проверяется отдельно — по загруженным пользователям. Шаг 2: `createProfileStepSchema(cityIds)` — имя, дата рождения (14–100 лет), пол (можно `null` — «Не указан»), город из справочника, «Хочу научиться» — от 1 до 10 подкатегорий; аватар в схему не входит и проверяется при выборе файла. Все поля — общие из `@/shared/lib/validation`
- `schema.test.ts` — правила обоих шагов: границы, пустые значения и тексты ошибок
- `types.ts` — Данные, накопленные по всем шагам. Хранятся в Redux, поэтому только сериализуемые значения: `File` не кладём в store; фото хранятся как готовые data URL (проверены `validateImageFile`, уменьшены `fileToDataUrl`), при сохранении (P6-06) повторно не сжимаются
