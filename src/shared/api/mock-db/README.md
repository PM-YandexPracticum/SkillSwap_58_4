# src/shared/api/mock-db

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

«База данных» внутри приложения: `createMockCollection` — коллекция с методами получить / создать / изменить / удалить. Образцы — JSON в `public/db/` (скачиваются через `fetch`), изменения — в localStorage. Потом её можно заменить на настоящую БД: меняется только слой `entities/*/api`.

## Что внутри

- `createMockCollection.ts` — коллекция «базы» (`getAll`, `getById`, `create`, `createIfAbsent`, `update`, `updateMany`, `remove`, `removeMany`) и `resetMockDb()` — сброс всех изменений к образцам. Действия одной коллекции выполняются по очереди. Изменения хранятся в localStorage, ответы приходят с задержкой `MOCK_DB.DELAY_MS`
- `createMockCollection.test.ts` — тесты: чтение и копии, изменения после «перезагрузки», повреждённый и недоступный localStorage, нехватка места, задержка, сброс; `updateMany` (сигнатура `getChanges`, пустой список, недостающий и повторный id, отсутствие лишнего `setItem`, `id` нельзя подменить); `removeMany` (свои и чужие записи, пустой `match`, отсутствие лишнего `setItem`, очередь при `create` во время удаления); `validateWrite` с `operation=update`; `updateMany` по актуальному снимку внутри очереди
- `isolation.test.ts` — проверка общего сброса из `src/setupTests.ts`: изменения «базы» не переходят из теста в тест
- `loadSeed.ts` — загрузчик образцов: `loadSeed('users')` скачивает `public/db/users.json` один раз; не скачалось — ошибка «Не удалось загрузить данные …», следующая попытка скачивает заново
- `loadSeed.test.ts` — тесты загрузчика: адрес файла, одна загрузка, нет файла, не список, HTML вместо JSON, нет сети
- `publicDb.test.ts` — проверка самих файлов `public/db`: количество записей, уникальные id, связи пользователей, навыков, городов и подкатегорий
- `index.ts` — публичный API — импортировать снаружи только отсюда

- `guards.ts` — примитивы runtime-проверки JSON (`isRecord`, строки, массив строк, ISO-дата).

`validate` в настройках коллекции проверяет каждую запись localStorage и seed. Обязательные поля
определяет сущность в своём api-файле. Неточный JSON со строковым id не считается корректным автоматически.
`loadSeed(name, validate)` удаляет ошибочный результат из кеша, чтобы повторная загрузка могла восстановиться.
Пустой сохранённый список допустим и не заменяется образцами.

`validateWrite(item, items)` — необязательное доменное ограничение для `create`/`update`.
Оно вызывается после runtime-проверки и до сохранения внутри существующей очереди коллекции.
Если проверка бросила ошибку, данные не записываются; очередь продолжает обрабатывать следующие запросы.
Проверка синхронная и не меняет переданные записи. Используется пользователями для уникальности email;
сам слой `shared` не знает ни об email, ни о Redux. Тесты включают параллельную запись из разных экземпляров коллекции.

`createIfAbsent(item, keyOf)` — в одной очереди читает коллекцию, возвращает существующую запись по доменному ключу или сохраняет новую. Существующая запись не перезаписывается. Используется предложением обмена для уведомления: повтор сохраняет прочитанность и дату. Вход копируется до ожидания очереди.

`validateWrite` получает третьим аргументом `create` или `update`: это позволяет проверять уникальность пары при создании и исключать собственную запись при обновлении. `createIfAbsent.test.ts` проверяет параллельные экземпляры и отсутствие записи поверх существующей. Mock-хранилище по-прежнему читает и сериализует JSON целиком; эта операция убирает лишние обращения из вызывающего сценария, а не заменяет localStorage настоящей индексированной БД.

`updateMany(getChanges, selectResult?)` вызывает синхронный расчёт изменений на копии актуального списка внутри очереди.
Колбэк возвращает пары `{ id, changes }`. Все id, структуры и доменные ограничения итогового списка проверяются
до единственного сохранения. При отказе ни одна запись не меняется; пустой список изменений ничего не записывает.
Обычный `update` использует этот же путь. Это атомарность одной коллекции в одной вкладке, не транзакция
между коллекциями или вкладками браузера. В P5-07 так вместе сохраняются избранное и счётчик лайков.

`removeMany(match)` — пакетное удаление записей, для которых `match` вернул `true`; остальные (включая чужие) не трогает.
Одно чтение, одна запись и одна задержка на весь пакет. Возвращает id удалённых записей. Если удалять нечего — в localStorage не пишет.
Используется очисткой уведомлений (P7-05).

Необязательный `selectResult` выбирает ответ из итогового снимка внутри той же очереди. Он позволяет вернуть весь список владельца после массового прочтения без второго `getAll` и задержки. Без него метод возвращает только изменённые записи, как прежде. Ответ всегда копируется; пустой набор изменений не записывается. `removeMany` вычисляет предикат ровно один раз на запись.
