# src/widgets/offer-card

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../docs/architecture/fsd.md).

## Зачем эта папка

Карточка предложения в каталоге: пользователь, визуальное избранное, ссылка на навык или статус «Обмен предложен».

## Что внутри

- [`ui/`](ui/README.md) — React-компонент, тесты и stories
- `index.ts` — публичный API — импортировать снаружи только отсюда

## Статус обмена (P7-04)

`OfferCard` использует `selectHasProposed(state, user.id)`: исходящее предложение текущего пользователя этому автору заменяет «Подробнее» на `ExchangeStatusBadge`, независимо от `skillId`. Гость и пользователь без такого предложения видят ссылку; одно входящее предложение её не меняет. Смена сессии сразу обновляет статус.

Карточка читает уже загруженный store. `CatalogPage` один раз запрашивает сохранённые обмены через `fetchExchanges()` при статусе `idle`, без отдельных запросов на каждую карточку. Ошибка обменов не блокирует каталог. При подключении ленты P5-06 используем этот же store. Интеграционный тест карточки проверяет сохранение обмена и повторную загрузку в новом store.

Figma: [каталог с предложенным обменом, 1:2106](https://www.figma.com/design/40gXmyAoxwwnb9kBxI5B8y/SkillSwap-Red.1-?node-id=1-2106). Бейдж — статичный текст, не кнопка, не ссылка и не live-регион: он не занимает остановку Tab, декоративная иконка скрыта от скринридера.

Город и интересы автора готовятся общими `getCityName` и `findSubcategories` из сущностей city/category.
Они же используются страницей навыка; неизвестные подкатегории пропускаются, порядок интересов сохраняется.

Поиск связанных навыка, города, категории и обмена идёт через общие индексы селекторов. Индексы строятся при смене коллекций, а не внутри каждой карточки; интересы используют общий индекс подкатегорий. Внешние props и порядок карточек не меняются.
