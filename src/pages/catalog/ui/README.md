# src/pages/catalog/ui

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **ui** слайса `catalog`. Содержит страницу и композицию каталога: вёрстка относится к P3-10, бизнес-подключение данных — к задачам фазы 5.

## Что внутри

- `CatalogPage.tsx` — соединяет данные пользователей/навыков, фильтры и поиск через `applyFilters`, строит плашки и передаёт списки и обработчики в `CatalogView`; единая область `<main>` и скрытый `h1`. После регистрации читает `location.state.offerCreated`, показывает `OfferCreatedModal` и сразу очищает state заменой текущей записи истории.
- `CatalogView.tsx` — композиция FiltersPanel и OffersSection; default и results-виды без повторной логики фильтрации и сортировки. Внутренний `FeedSection` подключает `useInfiniteScroll` к лентам «Рекомендуем» и результатов.
- `CatalogPage.module.css`, `CatalogView.module.css` — отступы страницы и две колонки компоновки; сетка карточек переиспользуется из OffersSection.
- `CatalogPage.test.tsx`, `CatalogView.test.tsx` — отображение загруженных данных, порядок секций, единая оболочка страницы, раскрытие секций, повтор карточек между секциями, загрузка обменов в StrictMode, ошибка обменов, переход на навык, догрузка лент и их сброс при новом списке, случайный порядок «Рекомендуем».

`OfferCard` показывает «Обмен предложен» по загруженному store. `CatalogPage` запрашивает обмены через `fetchExchanges()` только при `idle`; проверка актуального store предотвращает повторный запрос в StrictMode. Ошибка обменов не блокирует каталог, автоматического повтора при `failed` нет. Контракт описан в [README виджета](../../../widgets/offer-card/README.md#статус-обмена-p7-04).

## Граница P3-10

Данные карточек читает `OfferCard` из store. Стартовую загрузку и переход на страницу 500 при ошибке обеспечивает `DataProvider` в роутере.

«Популярное» получает `selectPopularUsers`, «Новое» — `selectNewUsers`: сортировки мемоизированы и не меняют порядок store. `CatalogView` требует оба готовых списка явно. Раскрытие 3 → 9 → 3 выполняет существующий `OffersSection`, карточки между секциями могут повторяться. «Рекомендуем» и результаты — бесконечные ленты (P5-06, см. ниже). Отдельный вид результатов задаёт внутренний объект `results`, который `CatalogPage` передаёт в `CatalogView` и показан в `app/CatalogPage` в Storybook; P5-02 уже записывает выборы панели в store, а список, плашки и сортировка подключены P5-05 (PR #194).

Stories страницы рендерят настоящую `CatalogPage` внутри `MainLayout`, без копии `<main>`, заголовка и отступов. Начальные фильтры и поиск передаются в store через `parameters` и `preloadedState`; плашки, сортировка и карточки читают то же состояние. `play` проверяет результаты и переключение сортировки. `ActiveFilters` и `SortToggle` также имеют отдельные управляемые stories.

Панель/карточка — 324 px, промежутки — 24 px, карточки всегда в три колонки. Макет — [1:2861](https://www.figma.com/design/40gXmyAoxwwnb9kBxI5B8y/SkillSwap-Red.1-?node-id=1-2861), результаты — [1:2860](https://www.figma.com/design/40gXmyAoxwwnb9kBxI5B8y/SkillSwap-Red.1-?node-id=1-2860). Пустые состояния в Figma не нарисованы. Ошибку основных данных и повтор загрузки показывает общая /500; отдельной кнопки повтора обменов в каталоге нет.

## Ленты P5-06

- «Рекомендуем» и «Подходящие предложения: N» показывают `CATALOG.SCROLL_BATCH` (6) карточек. Прокрутка к концу ленты — спиннер на `CATALOG.SCROLL_DELAY_MS` (1 с) и ещё 6. Без прокрутки следующая порция не грузится — так задумано в `useInfiniteScroll`.
- «Рекомендуем» берёт `selectRecommendedUsers` — порядок store, который `fetchUsers` перемешивает один раз. `applyFilters` всегда сортирует по дате, поэтому без фильтров его результат в ленту не передаётся; `shuffle` при рендере не вызывается.
- В Figma лента показана статичной сеткой без спиннера; положение спиннера под сеткой — решение вне макета (подробнее в README `widgets/offers-section/ui`).
- N в заголовке результатов — все совпадения, а не видимые карточки.
- Смена фильтров, поиска или сортировки даёт новый список из `useMemo` в `CatalogPage`, и хук начинает ленту сначала. Переход «каталог ⇄ результаты» монтирует ленту заново (`key`).
- «Популярное» и «Новое» не меняются: 3 ⇄ 9. Обмены по-прежнему загружает только `CatalogPage`.
- В jsdom нет `IntersectionObserver`: `src/setupTests.ts` ставит заглушку без срабатываний, а тесты догрузки подменяют её через `vi.stubGlobal`.
