# src/pages/catalog/ui

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **ui** слайса `catalog`. Содержит страницу и композицию каталога: вёрстка относится к P3-10, бизнес-подключение данных — к задачам фазы 5.

## Что внутри

- `CatalogPage.tsx` — единая оболочка обычного каталога и вида результатов (`results`), с загрузочным и ошибочным состоянием, одним `<main>` и скрытым `h1`; thunks временно запускаются до общей загрузки P4-04.
- `CatalogView.tsx` — композиция FiltersPanel и OffersSection; default и results-виды без повторной логики фильтрации, сортировки и догрузки.
- `CatalogPage.module.css`, `CatalogView.module.css` — отступы страницы и две колонки компоновки; сетка карточек переиспользуется из OffersSection.
- `CatalogPage.test.tsx`, `CatalogView.test.tsx` — загрузка без повторных запусков в StrictMode, готовый/загружающийся store, повтор только упавших коллекций, единая оболочка страницы, порядок «Популярного» по лайкам и «Нового» по дате регистрации, раскрытие 3 → 9 → 3, повтор карточек между секциями, однократная загрузка обменов, состояния и переход на навык.

`OfferCard` показывает «Обмен предложен» по загруженному store. Сохранённые обмены `CatalogPage` загружает одним запросом `fetchExchanges()` из `@/entities/exchange` (P5-04), только при `idle`. Обмены не входят в статусы, от которых зависит показ каталога: ошибка их загрузки страницу не блокирует. Для ленты P5-06 используется та же загрузка. Контракт описан в [README виджета](../../../widgets/offer-card/README.md#статус-обмена-p7-04).

## Граница P3-10

Данные карточек читает `OfferCard` из store. До P4-04 `CatalogPage` вызывает готовые thunks только при `idle`; повтор по кнопке — только для `failed`. Проверка актуального store предотвращает повторный старт при StrictMode. Thunks сами переводят ошибки API в `failed`: сырые исключения пользователю не выводятся. Готовые и уже загружающиеся коллекции не перезапрашиваются; число запусков каждого thunk проверяется тестами.

P4-04 остаётся владельцем общей загрузки при старте и страницы 500: при её подключении локальный запуск thunks и обработка загрузки/ошибки в `CatalogPage` заменяются общей границей `DataProvider`. Новую общую инфраструктуру загрузки P3-10 не добавляет.

«Популярное» (по убыванию `likesCount`) и «Новое» (по `createdAt` от новых к старым) получают списки из селекторов `selectPopularUsers` и `selectNewUsers` через props `CatalogView`; по 3 карточки, раскрытие до 9 делает `OffersSection` (P3-08), карточки могут повторяться между секциями (P5-04). «Рекомендуем» показывает первые `CATALOG.SCROLL_BATCH` без догрузки (P5-06). Отдельный вид результатов доступен через `CatalogPage.results` и показан в `app/CatalogPage` в Storybook; выбор фильтров и поиск пока не переключают страницу (P5-02/P5-05).

Все stories страницы рендерят настоящую `CatalogPage` внутри `MainLayout`, без копии `<main>`, заголовка и отступов. В Results и EmptyResults начальный выбор в панели выставляется через `play`, в SearchResults поле заполнено запросом из макета. Это статичные состояния вёрстки: callbacks плашек и сортировки записываются в Actions, а их локальное управляемое поведение показано в отдельных stories ActiveFilters и SortToggle. Синхронизация плашек с панелью и карточками относится к P5-02/P5-05.

Панель/карточка — 324 px, промежутки — 24 px, карточки всегда в три колонки.
