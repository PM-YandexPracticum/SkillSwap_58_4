# src/pages/catalog/ui

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **ui** слайса `catalog`. Содержит страницу и композицию каталога: вёрстка относится к P3-10, бизнес-подключение данных — к задачам фазы 5.

## Что внутри

- `CatalogPage.tsx` — единая оболочка обычного каталога и вида результатов (`results`), с одним `<main>` и скрытым `h1`.
- `CatalogView.tsx` — композиция FiltersPanel и OffersSection; default и results-виды без повторной логики фильтрации, сортировки и догрузки.
- `CatalogPage.module.css`, `CatalogView.module.css` — отступы страницы и две колонки компоновки; сетка карточек переиспользуется из OffersSection.
- `CatalogPage.test.tsx`, `CatalogView.test.tsx` — отображение загруженных данных, порядок секций, единая оболочка страницы, раскрытие секций, повтор карточек между секциями, загрузка обменов в StrictMode, ошибка обменов и переход на навык.

`OfferCard` показывает «Обмен предложен» по загруженному store. `CatalogPage` запрашивает обмены через `fetchExchanges()` только при `idle`; проверка актуального store предотвращает повторный запрос в StrictMode. Ошибка обменов не блокирует каталог, автоматического повтора при `failed` нет. Контракт описан в [README виджета](../../../widgets/offer-card/README.md#статус-обмена-p7-04).

## Граница P3-10

Данные карточек читает `OfferCard` из store. Стартовую загрузку и переход на страницу 500 при ошибке обеспечивает `DataProvider` в роутере.

«Популярное» получает `selectPopularUsers`, «Новое» — `selectNewUsers`: сортировки мемоизированы и не меняют порядок store. `CatalogView` требует оба готовых списка явно. Раскрытие 3 → 9 → 3 выполняет существующий `OffersSection`, карточки между секциями могут повторяться. «Рекомендуем» показывает первые `CATALOG.SCROLL_BATCH` без догрузки (P5-06). Отдельный вид результатов доступен через `CatalogPage.results` и показан в `app/CatalogPage` в Storybook; P5-02 уже записывает выборы панели в store, а список, плашки и сортировку подключает P5-05 (In Progress).

Все stories страницы рендерят настоящую `CatalogPage` внутри `MainLayout`, без копии `<main>`, заголовка и отступов. В Results и EmptyResults начальный выбор в панели выставляется через `play`, в SearchResults поле заполнено запросом из макета. Это статичные состояния вёрстки: callbacks плашек и сортировки записываются в Actions, а их локальное управляемое поведение показано в отдельных stories ActiveFilters и SortToggle. Синхронизация плашек с панелью и карточками относится к P5-02/P5-05.

Панель/карточка — 324 px, промежутки — 24 px, карточки всегда в три колонки.
