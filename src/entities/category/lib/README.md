# src/entities/category/lib

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **lib** слайса `category` — чистые функции без React и Redux. Легко тестируются и переиспользуются в компонентах и тестах.

**Текущее состояние:** функции реализованы и покрыты unit-тестами (P6-03).

## Правило связи категорий и подкатегорий (ТЗ п. 3.3)

1. Выбраны категории — в списке подкатегорий только их подкатегории.
2. Ничего не выбрано — видны все подкатегории.
3. Выбрана подкатегория — её категория отмечается автоматически.
4. Несогласованных пар не бывает: снятая категория убирает и свои подкатегории.
5. Работает в обоих режимах регистрации: шаг 2 — множественный выбор, шаг 3 — одиночный.

Оба режима обслуживаются одной сигнатурой с массивами: на шаге 3 передаётся массив из одного значения (или пустой).

## Что внутри

- `createCategory.ts` — фабрика категорий для тестов и stories, импорт через `@/entities/category/testing`.

- `linkCategories.ts` — правила связывания:
  - `getAvailableSubcategories(categories, selectedCategoryIds)` — какие подкатегории показать: не выбрано ни одной категории → все, выбраны → только подкатегории выбранных.
  - `syncCategorySelection(categories, selection, previous)` — приводит выбор к согласованному виду по правилам 3–4 выше. Третий аргумент `previous` нужен, чтобы отличить снятие категории от выбора подкатегории без категории: новое значение в этих случаях выглядит одинаково.

- `linkCategories.test.ts` — unit-тесты (15: 6 на доступные подкатегории, 9 на синхронизацию).
