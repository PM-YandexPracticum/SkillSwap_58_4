# src/entities/exchange/api

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **api** слайса `exchange` — единственное место, которое знает, откуда берутся данные (сейчас — «база» `shared/api/mock-db`). Переход на настоящую БД — меняется только этот сегмент.

## Что внутри

- `exchangeApi.ts` — `getExchanges()` читает сохранённые предложения; `createExchange(exchange)` проверяет пару `fromUserId + toUserId` и сохраняет запись. Проверка и запись стоят в одной очереди: два одновременных запроса не создадут дубль; другой `skillId` не разрешает повторное предложение тому же человеку. Обратное направление — другая пара.
- `exchangeApi.test.ts` — сохранение, неизменность входных данных, повторная пара и одновременные запросы.

API передаёт runtime-валидатор сущности в `loadSeed` и `createMockCollection`:
обязательные поля и вложенные массивы проверяются до передачи JSON в Redux.
Неверные сохранённые данные сбрасываются к образцам; неверный seed даёт ошибку загрузки с повторной попыткой.

`completeExchangeProposal(id, fromUserId)` снимает технический признак `notificationPending`, проверяя владельца по сохранённой записи. Создание и завершение используют одну очередь; повторное завершение безопасно. Необязательное поле проходит runtime-проверку, старые JSON-записи остаются валидными.

Проверка уникальности пары выполняется в `validateWrite` очереди коллекции: создание не вызывает предварительный `getAll`. Завершение исключает собственную запись из проверки дублей. Отдельная очередь API удерживает согласованность чтения и завершения предложения.
