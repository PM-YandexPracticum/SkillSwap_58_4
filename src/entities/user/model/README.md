# src/entities/user/model

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **model** слайса `user` — данные и логика: типы, Redux-слайс, селекторы, схемы валидации.

## Что внутри

- `selectors.ts` — мемоизированные `PublicUser[]` для UI, текущий пользователь `selectCurrentUser`, поиск по id, сортировки «Популярное» / «Новое», стабильный список «Рекомендуем»; `selectUserByEmail` — полная запись только для логики входа
- `selectors.test.ts` — публичный API, отсутствие паролей в UI-селекторах, email без учёта регистра, стабильность ссылок, порядка и сортировок
- `types.ts` — Пользователь платформы. Образцы — `public/db/users.json`; чтение и запись — только через `entities/user/api`
- `usersSlice.ts` — загрузка через `fetchUsers`, запись через `createNewUser` / `updateDataUser`; независимые состояния загрузки и сохранения
- `usersSlice.test.ts` — переходы состояний загрузки, ошибки и повторы, чтение образцов и localStorage
- `usersSlice.writes.test.ts` — сохранение/повторное чтение, неизменность и порядок, уникальность email, параллельные запросы, нехватка места и повтор записи

## Контракты P4-03

Снаружи импортировать функции из `@/entities/user`. `selectUsers`, `selectUserById`, `selectPopularUsers`, `selectNewUsers` и `selectRecommendedUsers` возвращают `PublicUser` без поля `password`. Проекция общая: повторные вызовы с неизменным массивом пользователей возвращают те же ссылки.

`selectUserByEmail(state, email)` возвращает `User | undefined`, включая учебный пароль. Он предназначен для **логики** входа (P4-09) и ранней проверки занятости email формой, а не для передачи в компоненты. Email сравнивается без учёта регистра и пробелов по краям. Окончательное ограничение уникальности находится в API, а не в селекторе.

`fetchUsers` сохраняет уже перемешанный массив в store. Селектор «Рекомендуем» только читает его, без новой случайности. При изменении лайков или профиля P4-06 сохраняет позиции записей; явная новая загрузка, в том числе после перезагрузки страницы, может дать новый порядок. «Популярное» и «Новое» сортируют копии и не меняют рекомендации.

`pending` очищает прежнюю ошибку, `rejected` сохраняет ранее загруженные данные, `fulfilled` заменяет данные и очищает ошибку. Технический текст исключения не передаётся в UI: понятное сообщение находится в `state.users.error`.

Подбор похожих предложений расположен в `pages/skill/model`: он объединяет пользователей и навыки через публичные селекторы. Модель user не читает состояние соседних сущностей.

Загрузочный thunk пропускает повторный dispatch, пока запрос в `loading`.
После завершения явное обновление и повтор после ошибки разрешены; начальную загрузку запускает общий `DataProvider` (P4-04).

## Текущий пользователь (P4-09 и P5-09)

`selectCurrentUser(state)` возвращает `PublicUser | null` по `userId` из сессии. Пароль исключён; изменение другой записи не создаёт новый объект текущего пользователя. Изменение его профиля, смена пользователя и выход обновляют результат. Факт наличия сессии определяет `selectIsAuth` из `entities/session`; селектор пользователя ничего не сохраняет и не выполняет dispatch.

Проверку сохранённой сессии выполняет [`RestoreSession` в `app/router`](../../../app/router/README.md). В P5-09 шапка читает готовые селекторы, а выход использует `endSession()`; собственный поиск пользователя и повторная проверка сессии не нужны.

## Сохранение (P4-06)

Публичные thunks: `createNewUser(user)` и `updateDataUser({ id, changes })`.
Сначала API сохраняет данные, затем `fulfilled` обновляет store новой записью.
Обновление сохраняет позицию пользователя; отсутствующая в store запись добавляется в конец.
Повторная загрузка и сохранение не дублируют id. Массивы и прежние объекты не изменяются.

- `status` / `error` относятся только к загрузке: `DataProvider` продолжает показывать текущую страницу во время записи.
- `saveStatus` / `saveError` относятся к записи; публичные селекторы — `selectUsersSaveStatus` / `selectUsersSaveError`.
- `pendingSaves` считает незавершённые записи. Статус остаётся `loading`, пока не завершатся все.
  Ошибка группы не теряется после успешного ответа другого запроса. Новая группа очищает прежнюю ошибку.
- Известные сообщения о повторе email и нехватке места сохраняются; остальные ошибки заменяются `DATA_ERRORS.SAVE_USER`.

Для результата конкретной операции вызывающий код использует `dispatch(thunk(...)).unwrap()` и обрабатывает отказ.
Регистрацию двух связанных записей собирает P6-06, сценарий лайков — P5-07, форму профиля — P7-06;
сами сценарии и транзакция между пользователями и навыками сюда не входят.

`selectUserById` ищет по мемоизированному индексу `PublicUser` за O(log n), не меняя исходный порядок и не возвращая пароль. Индекс обновляется вместе с публичным списком.
