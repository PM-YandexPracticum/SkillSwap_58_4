# src/entities/user/model

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **model** слайса `user` — данные и логика: типы, Redux-слайс, селекторы, схемы валидации.

## Что внутри

- `selectors.ts` — мемоизированные `PublicUser[]` для UI, поиск по id, сортировки «Популярное» / «Новое», стабильный список «Рекомендуем» и подбор похожих предложений; `selectUserByEmail` — полная запись только для логики входа
- `selectors.test.ts` — публичный API, отсутствие паролей в UI-селекторах, email без учёта регистра, стабильность ссылок, порядка и сортировок; подбор похожих по подкатегории, смена навыка и обновление данных
- `types.ts` — Пользователь платформы. Образцы — `public/db/users.json`; чтение и запись — только через `entities/user/api`
- `usersSlice.ts` — `fetchUsers` загружает всех пользователей через API и один раз перемешивает их для «Рекомендуем»; статусы `idle/loading/succeeded/failed`, понятная ошибка из `DATA_ERRORS`
- `usersSlice.test.ts` — переходы состояний, ошибки и повторные загрузки, чтение всех образцов `public/db` и сохранённых данных localStorage

## Контракты P4-03

Снаружи импортировать функции из `@/entities/user`. `selectUsers`, `selectUserById`, `selectPopularUsers`, `selectNewUsers` и `selectRecommendedUsers` возвращают `PublicUser` без поля `password`. Проекция общая: повторные вызовы с неизменным массивом пользователей возвращают те же ссылки.

`selectUserByEmail(state, email)` возвращает `User | undefined`, включая учебный пароль. Он предназначен для **логики** входа (P4-09) и проверки уникальности email (P4-06), а не для передачи в компоненты. Email сравнивается без учёта регистра и пробелов по краям. Сам вход, сессия и сохранение пользователя в этой задаче не реализуются.

`fetchUsers` сохраняет уже перемешанный массив в store. Селектор «Рекомендуем» только читает его, без новой случайности. При изменении лайков или профиля P4-06 сохраняет позиции записей; явная новая загрузка, в том числе после перезагрузки страницы, может дать новый порядок. «Популярное» и «Новое» сортируют копии и не меняют рекомендации.

`pending` очищает прежнюю ошибку, `rejected` сохраняет ранее загруженные данные, `fulfilled` заменяет данные и очищает ошибку. Технический текст исключения не передаётся в UI: понятное сообщение находится в `state.users.error`.

## Похожие предложения (P7-02)

`selectSimilarUsers(state, skillId)` возвращает `PublicUser[]` других авторов, чей **предлагаемый** навык
имеет ту же `subcategoryId`, что и открытый навык. Категория и «Хочет научиться» на подбор не влияют.
Порядок совпадает с `selectUsers`; селектор не сортирует и не ограничивает количество карточек.
Без текущего навыка, его подкатегории или совпадений возвращается пустой список.
Отсутствующий предлагаемый навык и ссылка пользователя на чужой навык пропускаются.

Селектор мемоизирован по публичному списку пользователей, массиву навыков и `skillId`.
Навыки читаются из `RootState`, без импорта соседнего слайса. Загрузкой управляет контейнер страницы,
а показом четырёх карточек и прокруткой — существующие `OffersCarousel` и `Carousel`.

Загрузочный thunk пропускает повторный dispatch, пока запрос в `loading`.
После завершения явное обновление и повтор после ошибки разрешены; начальную загрузку по-прежнему
запускают текущие контейнеры до общего DataProvider. Архитектура провайдера здесь не реализуется.
