# src/entities/user/api

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **api** слайса `user` — единственное место, которое знает, откуда берутся данные (сейчас — «база» `shared/api/mock-db`). Переход на настоящую БД — меняется только этот сегмент.

## Что внутри

- `userApi.ts` — Хранилище пользователей. Единственное место, которое знает, откуда берутся данные. Переход на настоящую БД — меняется только этот файл

API передаёт runtime-валидатор сущности в `loadSeed` и `createMockCollection`:
обязательные поля и вложенные массивы проверяются до передачи JSON в Redux.
Неверные сохранённые данные сбрасываются к образцам; неверный seed даёт ошибку загрузки с повторной попыткой.

- `userApi.test.ts` — неизменность данных при отказе, уникальность email для create/update и параллельных записей

`createUser` и `updateUser` сохраняют через общую коллекцию. `validateWrite` проверяет уникальность email
в той же очереди, что и запись: параллельные вызовы в одной вкладке не создают дубль.
Сравнение — через `normalizeEmail`, как у `selectUserByEmail`; свой id при обновлении исключается.
Проверка не зависит от Redux и выполняется также при прямом вызове API.
Ранняя проверка формы P6-02 остаётся подсказкой, а API принимает окончательное решение.
Нарушение возвращает `DATA_ERRORS.DUPLICATE_EMAIL`; отказ не меняет коллекцию.

`toggleUserFavorite(currentUserId, targetUserId)` — внутренняя операция API для thunk `updateUserFavorite`.
Читает актуальные записи в очереди коллекции и одной записью сохраняет `likedUserIds` владельца и
`likesCount` адресата. Отсутствующий пользователь и лайк себе отклоняются. Счётчик не опускается ниже нуля.
При нехватке места обе записи остаются прежними; ручной откат не нужен. На настоящем сервере этому
контракту должна соответствовать одна транзакция. Проверки сессии и повторного клика остаются в feature.
