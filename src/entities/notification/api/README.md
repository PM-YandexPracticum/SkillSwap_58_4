# src/entities/notification/api

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **api** слайса `notification` — единственное место, которое знает, откуда берутся данные (сейчас — «база» `shared/api/mock-db`). Переход на настоящую БД — меняется только этот сегмент.

## Что внутри

- `notificationApi.ts` — `getNotifications()`, `createNotification(notification)`, `markNotificationRead(id)`, `markAllNotificationsRead(userId)` и `clearNotifications(userId)`. Массовые действия затрагивают только указанного владельца; очистка удаляет и новые, и просмотренные записи. Чтение всех возвращает полный список владельца, включая уже просмотренные записи. Создание, чтение и массовые действия используют общую очередь `createMockCollection`; отдельной очереди в API нет. Массовые действия идут одним пакетным запросом: `updateMany` для чтения, `removeMany` для очистки — одно чтение и одна запись коллекции вместо N; ошибка записи пробрасывается наружу, ложного успеха нет.
- `notificationApi.test.ts` — разделение по владельцам, повторное чтение, очистка пустого списка, сохранение нового уведомления после очистки, снимок входных данных до ожидания очереди и переполнение хранилища при массовых действиях.

Функции API работают с переданными данными. Компоненты вызывают thunks из публичного API слайса: они определяют владельца по сессии и синхронизируют Redux с базой.

API передаёт runtime-валидатор сущности в `loadSeed` и `createMockCollection`:
обязательные поля и вложенные массивы проверяются до передачи JSON в Redux.
Неверные сохранённые данные сбрасываются к образцам; неверный seed даёт ошибку загрузки с повторной попыткой.

`ensureExchangeNotification` — операция P7-03 «вернуть или создать» по паре `userId + exchangeId`. Работает в очереди коллекции, возвращает ранее прочитанную запись без изменения даты, id и состояния. Повтор не требует получения всех уведомлений в feature. Обычная `createNotification` сохраняет прежнюю семантику создания.
