# src/entities/notification/model

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **model** слайса `notification` — данные и логика: типы, Redux-слайс, селекторы, схемы валидации.

## Что внутри

- `notificationsSlice.ts` — `fetchNotifications()` загружает список, `addNotification(notification)` сохраняет новое уведомление, `markAllRead()` читает новые (сохраняет в store и уже просмотренные записи владельца) и `clearAllNotifications()` удаляет все уведомления текущего пользователя. Гость не меняет данные; владелец нового уведомления должен совпадать с сессией.
- `notificationsSlice.test.ts` — сохранение и повторная загрузка в новом store, разделение пользователей, выход, запрет чужой записи, ошибки сохранения и частичные ошибки массовых действий.
- `selectors.ts` — мемоизированный `selectNotifications` отдаёт только уведомления владельца сессии, гостю — `[]`; `selectHasUnread` включает точку только для его новых уведомлений. Статус и ошибка — `selectNotificationsStatus` / `selectNotificationsError`.
- `types.ts` — `Notification`: один вид «Вы предложили обмен …», владелец `userId`, получатель предложения `toUserId`, ссылка `exchangeId`.

`items` содержит записи базы, а видимый список ограничивают селекторы. Соседнюю сущность `session` не импортируем: сессию читаем через глобальный `RootState`.

После успешной записи обновляется store; при ошибке сохраняются `status: failed` и понятное сообщение. Массовое действие меняет несколько записей по очереди: если часть сохранилась, а следующая запись завершилась ошибкой, thunk перечитывает базу и синхронизирует store. Операцию можно повторить. Атомарной транзакции между несколькими записями или между обменом и уведомлением в этой задаче нет.

`pendingRequests` учитывает все незавершённые запросы, в том числе восстановительную загрузку после ошибки. Пока есть активные запросы, статус остаётся `loading`; ошибка одного запроса не затирается успехом другого. Новая операция после завершения группы очищает прежнюю ошибку.

`ensureExchangeNotification(notification)` — thunk P7-03: проверяет сессию/владельца, получает или создаёт уведомление через API и объединяет фактически сохранённую запись со store. Участвует в общем счётчике запросов; обработчик результата переиспользуется с `addNotification`.
