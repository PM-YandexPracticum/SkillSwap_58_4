# src/entities/notification/model

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../../docs/architecture/fsd.md).

## Зачем эта папка

Сегмент **model** слайса `notification` — данные и логика: типы, Redux-слайс, селекторы, схемы валидации.

## Что внутри

- `notificationsSlice.ts` — `fetchNotifications()` загружает список, `addNotification(notification)` сохраняет новое уведомление, `markAllRead()` отмечает новые прочитанными одним `updateMany` и возвращает полный список владельца (включая уже просмотренные), `clearAllNotifications()` удаляет все уведомления пользователя одним `removeMany`. Гость не меняет данные; владелец нового уведомления должен совпадать с сессией. Поле `loadError` отделено от `error`; `pendingRequests` отслеживает незавершённые запросы — статус `loading`, пока группа не завершится, ошибка одного запроса не затирается успехом другого.
- `notificationsSlice.test.ts` — сохранение и повторная загрузка в новом store, разделение пользователей, выход, запрет чужой записи, ошибки сохранения и массовых действий.
- `selectors.ts` — мемоизированный `selectNotifications` отдаёт только уведомления владельца сессии, гостю — `[]`; `selectHasUnread` включает точку только для его новых уведомлений. Статус и ошибка — `selectNotificationsStatus` / `selectNotificationsError`.
- `types.ts` — `Notification`: один вид «Вы предложили обмен …», владелец `userId`, получатель предложения `toUserId`, ссылка `exchangeId`.

`items` содержит записи базы, а видимый список ограничивают селекторы. Соседнюю сущность `session` не импортируем: сессию читаем через глобальный `RootState`.

После успешной записи обновляется store; при ошибке сохраняются `status: failed` и понятное сообщение. Массовое действие (`markAllRead`, `clearAllNotifications`) выполняется одной пакетной операцией mock DB: `updateMany(getChanges, selectResult)` для отметки прочитанными, `removeMany(match)` для очистки. Одно чтение коллекции, одна запись в localStorage, одна задержка 300 мс на весь пакет. Меняются только записи владельца сессии; чужие сохраняются. При ошибке записи thunk отклоняется, store сохраняет прежний список: пакетная операция не записывает частичные изменения. Операцию можно повторить. Атомарной транзакции между коллекциями или вкладками в этой задаче нет.

`pendingRequests` учитывает все незавершённые запросы, в том числе первоначальную загрузку. Пока есть активные запросы, статус остаётся `loading`; ошибка одного запроса не затирается успехом другого. Новая операция после завершения группы очищает прежнюю ошибку.

`ensureExchangeNotification(notification)` — thunk P7-03: проверяет сессию/владельца, получает или создаёт уведомление через API и объединяет фактически сохранённую запись со store. Участвует в общем счётчике запросов; обработчик результата переиспользуется с `addNotification`.

Повторное массовое действие не запускается, пока `pendingRequests > 0`; UI также блокирует кнопки. Владелец фиксируется перед ожиданием API, поэтому смена сессии не переносит операцию на другого пользователя.
