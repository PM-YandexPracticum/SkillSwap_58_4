# src/app/providers

> **SkillSwap** — платформа обмена навыками (только фронтенд: React + TypeScript + Redux Toolkit).
> Архитектура — Feature-Sliced Design, подробности в [docs/architecture/fsd.md](../../../docs/architecture/fsd.md).

## Зачем эта папка

Провайдеры приложения подключают Redux, роутер, стартовую загрузку, уведомления и тему.

## Что внутри

- `RouterProvider.tsx` — все маршруты приложения, lazy-загрузка страниц, лейауты; RegisterDraftLifecycle внутри BrowserRouter очищает черновик при выходе из регистрации
- `ErrorBoundary.tsx` — корневая защита от ошибок рендера и жизненного цикла, включая провайдеры. Использует готовый ServerErrorView без роутера; «На главную» перезапускает приложение с учётом BASE_URL. Ошибки событий и асинхронных операций обрабатываются в своих сценариях
- `ErrorBoundary.test.tsx` — обычный экран, сбой без роутера/store в StrictMode, кнопки и BASE_URL; `App.test.tsx` проверяет ошибки маршрута и провайдеров
- `ErrorBoundary.stories.tsx` — обычное состояние и ошибка с экраном 500 по Figma 1:2077
- `DataProvider.tsx` — запускает загрузку пользователей, навыков, категорий и городов. Показывает Loader, открывает маршруты после загрузки и переводит на `/500` при ошибке
- `StoreProvider.tsx` — подключает Redux store к React
- `ThemeProvider.tsx` — Применяет сохранённую тему (`data-theme` на <html>) при старте приложения. ⭐ Необязательная фича (фаза 9): пока не реализована, просто отдаёт children
- `ToastProvider.tsx` — подключён в `App`, предоставляет `useToast` всем маршрутам. Выводит сообщения через портал в `body` в заранее смонтированной области `role="log"` / `aria-live="polite"`. У каждого сообщения свой таймер 4000 мс из `shared/config`; таймер отменяется и удаляется при закрытии, все активные таймеры очищаются при размонтировании
- `ToastProvider.module.css` — фиксированный список слева внизу, ширина 340 px по Figma. Длинный список прокручивается, оставляя сверху зону шапки (132 px); слой `--z-toast` находится выше модального окна, чтобы сообщения оставались видны. Пустая область пропускает клики на страницу
- `ToastProvider.test.tsx` — показ через хук, live region, независимые таймеры, закрытие мышью и клавиатурой, очистка при размонтировании в StrictMode
- `ToastProvider.stories.tsx` — интерактивная story `app/providers/ToastProvider/Interactive` с настоящим провайдером и несколькими уведомлениями
- `ToastProvider.stories.module.css` — оформление демонстрации на CSS-переменных

`DataProvider.test.tsx` проверяет границу загрузки и сохранения P4-06: запись пользователя/навыка,
включая отказ из-за нехватки места, не размонтирует открытую форму и не переводит её на страницу 500.

## Проверка загрузки и страницы 500

Backend отсутствует: методы учебной базы отвечают с задержкой 300 мс (`MOCK_DB.DELAY_MS`), чтобы показать Loader. При ошибке загрузки общих данных DataProvider открывает `/500`; ErrorBoundary показывает тот же вид при ошибке рендера. Случайных сбоев при обычном использовании нет.

Для визуальной проверки можно открыть `/500` напрямую или story `app/providers/ErrorBoundary/WithError`. Прямой переход показывает только экран; он не проверяет обработку отказа загрузки. В story ошибка в консоли ожидаема. Переход при отказе загрузки и повтор после кнопки «На главную» проверяются командой `npm test -- src/app/providers/RouterProvider.test.tsx`: тесты намеренно возвращают HTTP 404 для одного файла `public/db`, затем восстанавливают ответ. Это управляемая имитация ошибки, а не настоящий HTTP 500 от backend. Для ревью указываем способ воспроизведения, не добавляем случайные ошибки в рабочий сценарий.
